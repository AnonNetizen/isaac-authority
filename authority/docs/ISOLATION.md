# 单机 Lua 私有界面隔离实验（2026-10-10）

**有限模型实验通过，真实旧模组兼容与可玩联机仍未通过。** 本次实现可以在一台电脑运行，不启动游戏，也不修改已安装模组或存档。它验证了一条主机侧影子 Lua 环境路线：同一份未修改测试模组生成两个个人界面，世界修改只提交主环境的一份。

源码是 `research/isolation.py` 与 `research/context.lua`，入口是 `tools/run_isolation.py`。这部分是 Python / Lua 5.3 研究代码，尚未接入 Windows x86 观察器 DLL。包版本为 0.2.0；原生观察器仍是此前验证的 0.1.0 二进制。

后续 0.3.0 实现了独立的 [真实原生对象桥接](OBJECT_BRIDGE.md)，已通过 J460 枚举与值对象测试。下面的 Python 模型及真实模组探测尚未连接该桥接，其失败记录和限制仍然有效。

0.4.0 另用 C++ 与游戏自身 Lua DLL 实现了 [原生模组运行环境](NATIVE_MOD_RUNTIME.md)，将有限模型调用记录与原生值对象连接起来。本文的 Python 实现保持独立；它的持久检查点没有自动移植到原生环境。

## 本次实际验证

原有 `fixtures/legacy_chaos/main.lua` 没有修改或安装到游戏。它在更新中使用随机数、时间，在渲染中增加金币，并保存个人语言、位置和按键。固定模型种子为 20261010，结果见 `reports/single-pc-isolation.json`。

| 模型帧 | 主界面 / 横坐标 | 第二界面 / 横坐标 | 玩家 0 金币 | 主环境提交的写入 |
|---|---|---|---|---|
| 1 | `zh\|1\|1000033\|5` / 24 | `en\|1\|1000033\|5` / 124 | 6 | 更新 +5，渲染 +1 |
| 2，第二人按 M | `zh\|2\|1000066\|2` / 24 | `en\|2\|1000066\|2` / 125 | 9 | 更新 +2，渲染 +1 |
| 3，第一人按 L | `zh\|3\|1000099\|4` / 25 | `en\|3\|1000099\|4` / 125 | 14 | 更新 +4，渲染 +1 |

玩家 1 金币保持 0，因为模组明确修改 `Isaac.GetPlayer(0)`。这是两个个人界面环境的验证，不是双人战斗。语言值是 `zh` / `en` 标签，没有测真实字体排版或翻译。

重复第三帧没有重复修改世界、配置或检查点。重新创建 Lua 环境并重放已接受记录后，两个私有渲染计数都继续为 4，位置仍为 25 和 125。

新增 `fixtures/config_drives_world/main.lua` 是必须失败的反例：个人按键改变私有 `amount`，同一个渲染回调再按这个值增加金币。第二人的配置产生不同世界调用时，实验拒绝候选帧，保留上一次世界、两份配置和检查点；重建后私有计数继续为 2。**这个反例仍然不兼容。** 拒绝分歧避免了重复提交，却没有让所有旧模组正常运行。

18 项隔离测试还覆盖缓存函数引用、写后读、原始文字字节、重复/过期帧、回调返回分歧、磁盘错误、源文件冻结、检查点损坏和被 `pcall` 捕获的未支持 API。全部使用模拟 API，不等于 J460 验收。

## 执行与提交方式

两个 Lua 环境都在主机侧。主环境先执行更新回调，记录随机数、时间与世界 API 的调用顺序、参数和返回值；影子环境随后重放。渲染回调采用同样检查。个人输入、绘制和配置使用各自命名空间，可以不同。

回调在两个环境中分别计算；只有主环境的世界写入进入候选世界。调用或返回不一致则拒绝帧。成功时先原子替换单个模型检查点文件，再发布世界和配置。失败时从冻结源码与已接受输入重建环境，核对记录；无法重建则停止模型会话。

这里没有复制任意 Lua VM 内存或 upvalue。函数字节码导出不保存闭包的全部运行状态，本实验靠重新执行事件恢复私有变量。[Lua 5.3 手册](https://www.lua.org/manual/5.3/manual.html) 说明了闭包、upvalue、userdata 和 `string.dump` 的语义。

Lupa 的 `encoding=None` 保留原始字符串字节，关闭 Python eval / builtins 并限制属性访问。每个环境有内存限额和指令预算；真实模组探测另在带超时的子进程中运行。这些限制不是用于执行不可信代码的安全沙箱。[Lupa 文档](https://github.com/scoder/lupa) 是运行时配置依据。

## 未修改真实模组的只读探测

本机 EID 和中文配置菜单 Lua 源文件按哈希冻结；没有读取个人配置或存档。完整枚举探测另读取 J460 `resources/scripts/enums.lua`。游戏枚举与模组源码不在研究包中，报告只保留哈希和错误。

| 探测 | 实际结果 | 含义 |
|---|---|---|
| EID + J460 枚举 | `authority_sdk_definitions: unsupported BitSet128.native_adapter` | 枚举初始化失败，尚未执行 EID 主文件 |
| 配置菜单 + J460 枚举 | 同上 | 枚举初始化失败，尚未执行菜单主文件 |
| EID，仅最小模型定义 | `eid_config.lua:341` 缺少 `ButtonAction` | 最小定义不完整，不能证明兼容 |
| 配置菜单，仅最小模型定义 | `authority_mod: unsupported Sprite.native_adapter` | 到达原生精灵边界，加载失败 |

四次均失败，前后源码清单一致。省略枚举的两次只用于定位缺口，不是关闭游戏功能后的兼容验收。没有逐模组补丁或假对象通过。详见四份 `reports/isolation-*-probe.json` / `isolation-*-minimal-profile.json`。

## 当前边界与下一步

- 模型只有金币和文本，缺少实体、碰撞、房间、动画、原生 Font / Sprite / BitSet128 等 userdata 的身份与属性适配。不会复制或传输原生指针。
- 模型随机数来自 Python；JSON 按键排序以稳定重建。二者尚未验证为游戏实现的完全等价替代。
- 一次加载一个模组根目录，没有完整模组加载顺序、跨模组共享全局变量、原生回调参数/过滤和全部返回语义。不能推断 EID 与配置菜单组合兼容。
- 个人配置改变世界调用、调用数量或回调返回时会拒绝帧。真实菜单与世界逻辑能否通用隔离仍未解决。
- 输入中的控制器 0 映射到当前界面环境是实验约定；原生第二玩家输入和旧模组控制器语义未验证。
- 最多保留 1024 个实验帧，失败从开始重放，检查点会增长。没有长时游戏性能、实际暂停或重连结论。
- 检查点只保存模型记录与模拟配置。没有原生进度提交、Steam 通信、客机渲染、原生世界应用或双机 30 分钟记录。

下一项单机工作应是确定 J460 原生对象的所有权、身份与可序列化字段，并验证独立 Lua 环境能否通过通用桥接访问它们；随后验证原生更新和事务恢复。仅补几个枚举不能解决这些边界。真实双机验收仍保留，缺少第二台电脑不妨碍接入点研究。

## 复现

在解压包根目录执行；本地源码工作区把 `source` 改为 `authority`。演示使用自己的输出目录，指定运行目录已存在时拒绝覆盖。

```powershell
py -3 -m pip install lupa==2.6
py -3 .\source\tools\run_isolation.py --demo --output .\runs\isolation-report.json
py -3 .\source\tests\test_isolation.py

# 只读加载探测
py -3 .\source\tools\run_isolation.py --probe-mod '完整模组目录' --definitions '完整游戏目录\resources\scripts\enums.lua' --output .\runs\mod-probe.json
```

`limited_model_experiment_passed=true` 只代表演示通过；`playable=false` 和 `generic_mod_compatibility_passed=false` 仍有效。加载探测退出码表示报告成功生成，必须读取报告的通过字段判断结果。
