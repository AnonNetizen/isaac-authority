# 固定容量记账缓存

上一候选的真实初始化 5 秒采样中，记账占约 17%～29%，调用约 291 万～411 万次。优先去掉每次重复字符串分配和红黑树查找，不改被收取的工作量，也不删证据。

1. 独立 Windows x86 候选 `ia-lua533-ledger-cache-1`，保留上一候选。每个预算上下文有 512 个固定缓存槽（x86 为 4096 字节）；按地址选槽，完整比较自有字符串才可命中。可变地址、相同内容不同地址、冲突都回到规范计数表。规范表只允许内部插入和更新；禁用预算对象复制，避免缓存引用失效。未知标签保持原路径和原语义，不把地址当身份。
2. 原记账路径由 `IA_LEDGER_LEGACY_LOOKUP=1` 选择，仅作有限对照。零工作量标签、恰好到上限、拒绝前不增加计数、首个错误锁存和采样页都保留原行为。
3. 先做原生计数/错误/采样一致性和 5 秒内微基准，再跑冻结 37 项模型、4 项容量的证据淘汰案例和同 DLL 短基准。完整比较个人/权威结果、逻辑事件、图、证书及每项预算计数。
4. 短门槛通过后各运行一次真实 MCM、EID、组合初始化；每子进程仍 5 秒、1000 万工作单位。未完成就报告失败，禁止推断完整开销。
5. 审计格式、资源、模组源码、个人存档和奖励规则不变。不启动游戏。原始审计核验后移除，不复制模组、不打重复 ZIP，保留唯一完整证据和二进制哈希。

验证调整：跨进程的字段索引比较/移动次数已有地址布局差异，诊断中的文件路径字节数也影响编码收费。因此不能用不同执行的最终总数代替逐次收费验证。`IA_LEDGER_VERIFY=1` 只在短模型中启用：同一次执行的每次收费送入独立旧记账器，检查本次键、总数、异常字节和首错锁存；执行与诊断边界再检查完整计数表。正常基准和真实初始化关闭镜像。跨进程实际收费仍原样记录，不删掉这些差异。
