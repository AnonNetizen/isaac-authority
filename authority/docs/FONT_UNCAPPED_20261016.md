# 最新 API 边界原型：临时无配额测量

2026-10-16，按用户要求，同时测试金币模型和冻结的真实 MCM/EID 初始化。两部分均完成；真实组合初始化约 0.80–0.89 秒，约 256 万工作单位。本轮没有出现此前几十分钟的初始化等待。

临时运行时为独立 Windows x86 可执行文件 `build-font-measurement/Release/authority-font-measure.exe`，ABI 为 `ia-lua533-font-measure-1`。基线为 `research/font_metrics_candidate_v1.json`。正式代码、EXE、Lua 静态库、冻结模组源码和候选入口均经前后哈希核对，未改动。

## 测量范围

临时版本移除工作总量、5 秒子进程超时、1 GiB Job 内存配额，以及记录、对象、字段、回调、绘制队列和报告的人工容量上限。只改变独立派生源码，没有重新编译 Lua，也没有加载旧的全量追踪运行时。物理内存、x86 地址空间、Lua/C++ 表示范围和调用栈仍然有限。

冻结哈希、资源完整性、API 参数语义、未知操作拒绝和世界写入权限保持生效。故意无限循环的 `work-limit` 案例不执行，因为它没有有限的完成点。派生差异及逐项移除的容量条件记录在 `build-font-measurement/derivation.json`。

共 110 个不同案例：64 个字体/API/配置/恢复案例、37 个字段和 upvalue 写屏障案例、6 个有限压力样本，以及 MCM、EID、组合初始化。真实初始化再各执行一次，共 113 次独立进程。初始化分别建立主机和个人上下文；组合在每份上下文中编译 124 个模块。

## 功能与重复运行

第一轮 110 个案例均达到各自功能或明确拒绝预期。字段、rawset、表库写入、共享闭包、GC、配置恢复、个人设置独立及主机单次加金币检查通过。缺失字体依赖的进程级失败保持为预期拒绝，不计兼容成功。

三种真实初始化与正式版本的可报告状态、步骤输出相同，两次临时运行也相同。**精确工作计数重复检查有两项不满足**：EID 相差 340，组合相差 1,454，最大约 0.057%。差异只出现在 VM 预付指令和读取计数，API、编码、世界写入及对象写入计数相同。已有正式版本和原版 Lua 对照记录也存在工作计数波动；本轮没有逐调用定位其根因，不将其解释成已证明的某一种原因。

原始 `summary.json` 的严格总判定为 false，原始报告原样保留。`review.json` 分别记录：首次 110 项分类检查满足、三项重复状态相同、两项精确工作计数不相同。没有重新定义原始失败，也没有补跑到得到相同计数为止。
