# 读取时值与版本绑定

独立 Windows x86 候选 `ia-lua533-bound-values-1` 完成所列模型短测。字段与 upvalue 的精确写屏障、消费者读取集合继续通过原清单回归；本候选进一步把可支持的绘制参数模板绑定到**读取发生时**的值、版本和函数调用实例，用独立原版 Lua 核对计算结果。

旧模组源码不改、个人配置独立、奖励跟随主机仍是完整目标。本轮只核对个人环境实际执行的参数，没有接回主机贡献、双视图选择或真实 MCM/EID；不能据此宣称奖励投影、联机或任意模组兼容通过。

## 实现与范围

捕获程序复用已修复的 `read_lua.lib`，没有重新构建解释器。只有显式 `capture_bindings` 动作开启少量调用/返回钩子及现有字段、单元读取入口的观察器；初始化和原有运行方式不开启该观察器。没有逐指令历史、全量值图或历史审计文件回读。

每次实际 GETUPVAL、GETTABUP、GETTABLE 记录对应的值、指令、捕获单元/字段编号和写入版本。记录带上下文代次、本轮捕获编号、主客角色及动态调用实例。表只保存本地寿命编号，不复制指针或阻止 GC。浮点保留位模式，字符串保留原始字节。只有直接表查询能够绑定；元方法结果需要额外摘要。

每个活跃函数保留每个源位置的最新观察；重复位置标为需要执行路径证明。真正的 RenderText 调用取得当时的不可变引用。未被绘制引用的记录随函数返回释放；异常退出的栈在后续钩子处清理；新捕获释放上一轮快照。同一个辅助函数两次调用使用不同实例，不靠源码行、最终数值或调用次序配对。

独立验证程序链接未修改 Lua 5.3.3 静态库。它只加载已校验的编译器原型、检查实际指令与参数定义，并用原版标量运算核对文本原始字节和整数坐标，不执行模组函数或世界 API。参数入口快照可证明本次观察到的值，但不证明调用者或初始化来源。缓存字符串不会从后来改变的配置重新计算。

支持直线式常量、参数、直接 upvalue/表读取、算术和拼接。函数返回/写入摘要、分支、循环、Lua 尾调用实例、元方法结果、C 包装参数映射、跨帧生产来源仍未解决；未知来源明确未解析。原生捕获仍输出 `bindings_verified=false`，验证器单独输出范围较窄的 `frame_values_verified`。全部 `origins_verified`、缓存复用、主机投影和界面发布开关保持 false。

## 验收结果

冻结清单为 `research/bound_values_v2.json`，原 18 项清单保留。21 项新案例的分类如下：

| 类别 | 数量 | 结论 |
|---|---:|---|
| 支持的观察参数复核 | 12 | 原版 Lua 运算、实际绘制、值及版本一致 |
| 缺少来源/路径证明 | 7 | 明确未解析，仅证明诊断正确 |
| 保存及绘制后失败恢复 | 1 | 配置、私有计数与绘制恢复；其输入分支仍未解析 |
| 观察负载容量拒绝 | 1 | 撤销全部暂存，重建后没有残留记录 |

功能案例包括修改前后查询、A→B→A（相同值的版本为 0 和 2）、中英文与 NUL/0xff、别名和嵌套表、不同辅助函数实例、缓存字符串跨帧、整数/浮点算术，以及捕获前已被 pcall 接住的错误。辅助函数入口值正确不等于其调用者生产链已获证明。

另有 8 项扰动检查：捕获哈希、查询键、源值、命名空间、缺失版本、交换相同数值结果的 ADD 操作数、常量改写及零预算。全部拒绝错误证据。尤其操作数交换不能仅凭数值恰好相同通过。

原 50 项读取集合、38 项写屏障、18 项初始化衔接、12 项紧凑索引、11 项绘制模板按原模式/原源码/原预期回归，共 129 项。保留旧写屏障宏重复求值的历史缺陷结论，使用已修复库执行，未再次运行故障旧 EXE。

最终两次完整批次约 11.93 和 11.77 秒，包含独立参考、每例两次候选运行、验证器、扰动及旧回归。该批次时间不是单进程超时。第一批新案例原生计时最长约 13.35 毫秒；原生子进程墙钟最长约 49.4 毫秒；捕获、模板分析及验证合计最大 10,084 工作单位。这是小模型样本，不能推断真实 MCM/EID 初始化速度。

回收案例累计创建 520 条观察，结束只保留绘制引用的 8 条，未持有全量历史；连续 24 次捕获只保留最新一轮的 4 条。记录的序列化负载不是 C++ 实际堆大小。恢复层仍保存已接受命令历史，因此没有证明长期联机会话总内存固定。

## 配额、事务与历史记录

保持 1000 万合计工作上限、每个原生/验证子进程 5 秒、1 GiB 进程配额；分析器也有独立 5 秒期限。观察参数、调用钩子、编码及验证工作额外计费，原 Lua 预付计费不减少。原版 C 库内部成本尚未逐指令计费，超时与进程配额继续约束它。

观察层最多 4096 条活跃记录、256 KiB 序列化负载、32 个活跃 Lua 函数、128 个绘制快照和 16384 个快照索引；原有消费者、字段、模板和节点上限保持。预算或能力超限不自动扩容。

原生捕获异常可通过原会话重建恢复配置、世界、RNG、私有变量和绘制。**离线验证在捕获进程结束后进行，尚未成为帧事务的提交条件。** 验证失败会报告拒绝，不能声称它已撤销先前结束进程中的状态；所有绘制仍未发布。

保留早期编译失败和冒烟记录说明：首次冒烟发生在 EXE 尚未生成时，没有执行模型；其后修复了重复生成函数和 C 桥缺少 opcode 头文件。18 项初测通过。增加回收用例后的首次检查仅在两次 GC 存储峰值相差 1 个字段、5 字节键负载处失败；值、编号、版本和绘制完全一致。最终比较仅排除 `peak_fields` 与 `peak_owned_key_bytes` 两个分配/GC 观测峰值，仍严格比较所有实际证据及其版本，不忽略其他失败。原失败结果无损保留。

没有修改冻结模组、个人存档、原版 Lua、历史候选或游戏文件，没有启动游戏或创建资源副本、研究 ZIP。详细结果经逐字节校验后压缩；只删除本候选可再生构建中间文件。
