# 回调读取集合与写屏障修复

当前候选是 `ia-lua533-boundary-reads-1`，独立 Windows x86 命令行程序。冻结 50 项案例通过：41 项功能、6 项安全拒绝、3 项不允许复用的诊断。另将原 38 项写屏障和 18 项边界衔接清单按原源码、原预期运行，56 项回归通过。最后对曾出现证据不稳定的错误路径另启 12 个短进程，读取集合、版本、普通结果均一致。

这证明了所列模型中的实际回调读取与失效检查，没有证明任意旧模组兼容、单条绘制参数投影或可玩联机。个人绘制仍不可发布，缓存不会跳过执行，主机奖励引用尚未接回。

## 修复上一轮遗漏的缺陷

原写屏障将 `settt_(o,t)` 改成同时写标签与通知监听，但重复使用了宏参数 `o`。Lua 源码中存在 `setnilvalue(L->top++)`、`setnilvalue(ra++)`、`setnilvalue(&f->k[oldsize++])`，导致目标表达式执行两次。常量槽因此跳过初始化，较大源码编译时 GC 的 `traverseproto` 出现访问异常。之前 38 项小模型通过，未覆盖这个缺陷。

新候选用一次求值的内联函数完成写标签和通知，不改变 Lua 数据布局。独立 C 探针使用保留的旧头文件，确定性复现目标求值两次；新头文件只求值一次。新增 80 个独立字符串常量、缺失函数参数、连续 nil 局部变量、30 次显式 GC，以及普通 Lua 对照，覆盖此前遗漏的路径。

**旧 `authority-writes.exe` 保留作历史故障对照，不能继续当作稳定运行入口。** 旧文件、清单和报告哈希保持；其旧校验器只验证历史文件，并不能推翻这里的新反例。当前入口见 `research/boundary_current.json`。

首次失败包括 5 秒终止、无诊断访问异常、带符号 `traverseproto` 栈。原故障 EXE 和诊断 EXE 保留为校验后的压缩文件。后续一次测试提前于重链结束启动，造成链接/启动冲突，未计为功能结果；中断记录单独保留。普通参考后端还修正了“已移除消费者”的诊断可用性，Lua 执行逻辑与冻结反例没有改写。

## 读取集合的范围

在真实登记回调的一次执行窗口中，记录实际读取的字段和捕获单元。嵌套辅助函数、工厂闭包、缓存函数仍执行原 Lua 代码；第一次访问时才登记相关单元，不递归扫描整张表或闭包。相同依赖去重，只保留每个消费者的最新集合。

- 普通索引、rawget、C API 的索引路径；字符串和整数键独立。缺失字段也记录，新增再删除会改变版本。
- `__index` 的缺失字段、对象元表绑定、实际查询到的元方法及后备表。原始读取不受无关元表更换影响。
- `pairs`/`next` 的结构和实际返回字段；`ipairs` 的实际下标与终止位置；长度的结构版本，普通长度另含元表依赖。修改无关下标不使 `ipairs` 摘要失效。
- upvalue 实际单元和版本，包括嵌套闭包的单元。共享消费者分别持有监听；移除最后一个所有者释放记录。GC 不被监听对象引用阻止。
- 单独的输入键、金币修改修订、私有存档存在性或存档内容哈希。LoadData 不在每个消费者中复制整份配置文本。
- 已登记原生调用身份。未知 C 函数在执行前拒绝，错误被 pcall 吞掉仍使整个帧失败。支持的原生函数仍执行原算法，不用空操作代替。

一次回调内读写同一字段会标出不同时点；外部 GC 调用明确不具备复用证书。此时仍执行真实 Lua 并核对画面命令，不能将“未重复世界写入”算作投影成功。

## GC 证据稳定性

最终复核发现，收集器内部的 `__mode` 检查偶尔被算作模组读取，还改变了第一次登记的表编号。即使画面完全一致，两次证据也会不同。

新候选仅让 `lgc.c` 的两个内部发现入口沿用原始、不采集读取集合的元方法查询；没有禁用 GC，也没有忽略同名字段的 Lua 查询。GC 清除仍进入原写屏障，实际终结回调仍通过正常 VM/API 读取钩子。新增案例证明普通 Lua 的 `__mode` 读取照常失效，真实 `__gc` 中的配置读取和绘制照常捕获。没有放宽两次结果完全一致的标准。

## 资源和验证

保留 1000 万工作上限、每子进程 5 秒及 1 GiB 内存配额；初始化、恢复、读取、写入和编码均纳入原有分项账本。标准 C 算法内部成本尚未全部逐项计费，由外部超时和进程配额补充约束，不能把工作单位当作完整 CPU 指令数。

每上下文最多 256 个消费者、1024 个监听字段、1024 个捕获单元；每消费者最多 1024 个内部依赖和 1024 个外部记录。总读取条目上限 16384，键和外部令牌各最多 4096 字节。超限明确拒绝，失败后重建已接受历史，包含此前已生成的回调摘要。

最终批次约 12.3 秒，包含进程启动、原版参考、两次候选运行、56 项回归和 12 次稳定性复测。单个子进程最大约 0.233 秒。2 万次字段读取的案例约 21.1 毫秒、281206 工作单位；实际 60042 次各类读事件只保留 8 个内部依赖、13 个输入令牌、4 个选定字段。连续替换 20 次仍只保留一个集合、8 个内部依赖和 4 个选定字段。这些是短模型数据，不推断真实 MCM/EID 的性能。

无逐值图、逐指令证据或正常审计输出。仍有后续空间：集合内键表示尚有重复，恢复层仍保留已接受命令历史；本轮不能证明长时间联机会话总内存固定。

当前是**按回调汇总的实际读集合**，还没有按单条绘制参数拆分，也没有从缓存字符串、算术、条件和跨帧值自动恢复最小表达式。因此 `versions_valid` 仅作诊断，所有 `reusable` 仍为 false。Lua 动态源码加载、未登记原生函数和更广的 userdata 契约尚未支持；支持列表外明确拒绝，不能将这些拒绝算作旧模组兼容。
