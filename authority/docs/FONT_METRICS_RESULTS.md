# 字体度量与真实源码初始化

本轮独立 Windows x86 命令行候选为 `--font-suite`，ABI `ia-lua533-font-metrics-1`。冻结的 MCM 中文版、EID、MCM→EID 组合均完成研究环境中的初始化；两次完整运行的可观察状态一致。**菜单导航、实际渲染回调、绘制发布、用途隔离和联机门槛仍未通过**。旧模组源码、游戏 DLL、个人配置文件和存档均未修改，没有启动游戏。

初始化的含义是：两份私有 Lua 环境执行冻结模块正常返回，登记回调、配置存储、精灵和字体状态可读取，原版 Lua 与研究 Lua 的已导出状态一致。它不证明全部私有 Lua 状态、所有 API、所有回调或游戏内行为等价。使用的版本、资源、枚举和场景仍是明确冻结的研究输入。

## 实际字体与内存

加载 14 份本机 BMFont v3 字体及其 44 个独立文件依赖，合计约 18.3 MB；安装目录保留原文件，包内没有复制字体或 PNG。独立 Python 解析冻结行高、基线、字形数和紧凑度量签名，C++ 从实际文件按需解析后重新校验签名。14 个固定测试串宽度均与 `runs/runtime-suite-final-j460-20261010/mod-runtime.json` 中通过的原生预检查对应。

运行时保留排序的字符编号与有符号 advance，缓存按冻结资源数封顶，不生成每字形 JSON 依赖节点。字体对象只保留资源身份、资源版本及缺字设置版本；PNG 校验后只保留读取句柄，不常驻其整份像素数据。跨上下文共享不可变索引，Font 对象状态独立，GC 时撤销 userdata 根与对象状态。

支持 Font、Load、IsLoaded、GetStringWidth、GetLineHeight、GetBaselineHeight、SetMissingCharacter、Unload，以及原样执行的 J460 GetStringWidthUTF8 包装。旧式空字符串 Load 参数已登记；未知参数、资源或对象操作继续拒绝。路径归一化只接受唯一对应的冻结身份，允许已验证源码根到安装资源根的映射，不为 EID 或 MCM 增加名字判断。

接口依据为 [Font API](https://wofsauge.github.io/IsaacDocs/rep/Font.html)，数据解析依据为 [BMFont 格式](https://www.angelcode.com/products/bmfont/doc/file_format.html)。历史原生控制只覆盖固定测试串和登记操作，不能代替所有文本或像素对照。中文 BMP 字形使用实际文件度量；未知默认缺字、配置了却不存在的替代字形、控制字符、多行、无效 UTF-8、代理对和未验证 kerning 明确拒绝。加载后缺字策略标为未知，直到显式 SetMissingCharacter；这不是对原生默认或重载策略的推断。

## 精确读取与恢复

普通已存在字符的宽度读取只依赖字体资源版本。确实遇到缺字时才加入缺字设置版本；无关设置写入不使正常宽度失效，缺字设置 A→B→A、资源重载和卸载会使相应读取失效。这是旧整数回调模式中的查询验证，新的 J460 回调框架仍明确拒绝消费者捕获，不将局部字体读取通过扩大为真实菜单依赖隔离通过。

验证个人位置、配置保存及字体选择独立，金币由主机提交一次。保存、字体状态变化及文本入队后注入失败，再按检查点与已接受历史重建；检查配置、字体与队列恢复。重复解析缓存、缓存方法、GC、错误文件哈希/大小、错误度量签名、缺失 PNG 依赖、对象上限和文本上限均有独立检查。

## 报告与日志分离

首版真实尝试已经正常退出，但标准 Lua print 的消息混在 JSON 前面，旧读取器因此判为无结构化报告；原始结果、二进制和源码快照保留。修正版在进入 Lua 前保留独立报告句柄，将标准输出诊断重定向到诊断管道，C++ 报告直接写入保留句柄。模组的 print 函数和 tostring 逻辑原样执行，没有删除日志或修改模组源码。

父进程边读取边限制报告为 2 MiB、诊断为 256 KiB，超限终止并回收进程；即使进程已正常退出，超额输出仍被拒绝。完整保存限额内的诊断字节，NUL 和非 UTF-8 字节不影响 JSON。另验证原生超额报告返回明确错误，避免将其当作成功状态。额外诊断配额测试独立统计，不计为模组兼容。

## 结果

最终 64 项新检查运行两轮，39 项功能/恢复检查、25 项预期拒绝均达到各自要求；原 44 项回调清单原样回归。另有一次输出配额案例，分别用原版 Lua、两次研究 Lua执行。完整结果、步骤、字体和精灵状态在重复运行中一致。

| 真实冻结源码初始化 | 研究运行时间 | 工作单位 | 结束时私有提交 |
|---|---:|---:|---:|
| MCM 中文版 | 约 0.119 秒 | 429,863 | 约 6.73 MiB |
| EID | 约 0.717 秒 | 2,028,339 | 约 56.89 MiB |
| MCM → EID | 约 0.783 秒 | 2,559,681 | 约 56.10 MiB |

这些读数来自 `font-metrics-real-v2` 的第一份研究运行，不含启动及外部审计；结束时提交量不是峰值，也不是长期会话泄漏测试。组合实际在两份环境中各编译 124 个模块，字体索引只解析 8 个已用资源。所有尝试保持 1000 万工作单位、5 秒子进程和 1 GiB 配额，没有启用全量追踪或扩大预算。

最终两个模型批次约 24.80 秒和 24.90 秒，包含每项三次独立进程和保护审计。正常完成/恢复案例的原生运行最高约 0.074 秒，最高 179,903 工作单位，结束时私有提交最高约 6.09 MiB。预期进程级拒绝单独按错误结果判定。
