# 紧凑依赖索引与绘制位置模板

本候选 ABI 为 `ia-lua533-compact-reads-1`。保留已验收的 read-set 原型及全部旧源码、二进制、报告；复用同一份已修复的 Lua 静态库，没有重新构建解释器或启用全量追踪。

当前完成两个步骤：减少消费者依赖记录的重复字符串；把金币模型中实际 Lua→RenderText 调用的位置接到反向表达式模板。**模板还没有绑定发生时的值和版本，不能用来投影奖励、跳过回调或发布界面。** 原要求仍是旧模组源码不改、个人配置独立、奖励跟随主机；这些完整功能没有因本轮检查通过而被宣称完成。

## 数字索引与回收

每个监听字段获得当前上下文内不重复的数字编号。带类型的键只由中央字段表保存，消费者记录 `(依赖类型, 对象寿命, 字段编号)` 与版本，不再保存键文本，也不拼接字符串索引。借用的 `string_view` 只用于当前查询；新增监听时才复制键。

活跃编号索引直接解析字段版本，不遍历整张表重建索引。最后一个所有者移除或表被 GC 回收时，先注销编号，再释放键；之后同地址、同字段名也获得新编号。上下文重建后的编号属于新代次，导出的字典明确携带代次。不能把这些本地编号作为跨进程身份。

默认保留旧式展开诊断以回归；`consumer_status` 的 `compact=true` 只返回字段编号，`field_dictionary` 按需单独给出活跃键和所有者数量。退休字段只保留失效的编号引用，不解引用已释放的键。所有消费者仍只保留最新集合。

独立 Win32 C++ 探针结果：

| 数据 | 原版读取集合 | 本候选 |
|---|---:|---:|
| Dependency 结构 | 72 字节 | 40 字节 |
| 映射键和值 | 96 字节 | 64 字节 |
| 消费者中的键/字符串索引负载 | 随消费者重复 | 0 |

这些结构大小不含树节点、分配器或 Lua 自身开销，不等同于整个进程内存。

128 个 1024 字节键由 12 个消费者读取时，旧消费者中两份长键副本的负载至少为 3,145,728 字节；新候选没有这部分副本，全部中央键负载为 131,109 字节。键字典核对了实际字节总量以及每个长键的 12 个消费者所有者。

单独执行回调、没有展开状态和字典文本的短样本：

| 指标 | 原版读取集合 | 本候选（两次） |
|---|---:|---:|
| 工作计数 | 49,558 | 49,558 / 49,558 |
| 原生耗时 | 19.39 ms | 11.65 / 11.81 ms |
| 结束时私有提交 | 6,414,336 字节 | 2,793,472 / 2,801,664 字节 |

这是本机小模型样本，未测统计显著性或长时峰值，不能推断真实 MCM/EID 的速度。改善没有依赖减少计费或提高预算。

12 项新索引案例通过，其中 10 项功能、2 项容量/事务拒绝；另有原 50 项读取集合、38 项写屏障、18 项衔接清单共 106 项回归通过。覆盖长键共享、主客配置交换、4096 字节边界、A→B→A、兄弟字段、整数/字符串/NUL/中文键、GC 后重建、连续替换、失败回滚和上下文代次。4097 字节键拒绝属于元数据能力边界，原版解释器没有该限制，单独列出，不作为模组兼容成功。

## 实际绘制位置与模板

新增可选 `capture_plans` 动作。它沿实际 Lua 调用栈取得函数与当前字节码指令，记录 RenderText 参数窗口和命令序号。函数的原始 Lua 5.3.3 字节码只按哈希保存一份；有界快照读取期间暂停研究运行时自身的读取采集，避免把检查器的查询算成模组依赖。正常 `capture_reads` 不创建这些快照。

只读分析工具校验字节码哈希和 ABI，再从实际参数寄存器反向查找定义，生成有序的常量、upvalue、表查询、算术、拼接及参数模板。常量字符串保留原始字节，浮点常量保留位模式。相同的静态生产位置可以共享节点，不按最终数值、字段名用途或界面文字合并。

模板检查包括：同一源码行的两个绘制调用具有不同指令位置；`100-amount` 与 `x-100` 保持操作数顺序；同一局部变量的源位置在两次显示中保留；文本与坐标使用各自表达式；NUL/0xff 字面量不被重新编码；尾调用记录实际 TAILCALL 指令。

函数调用可能通过子闭包改写捕获的局部变量，不能只检查返回寄存器。新增反例中先读取 amount，再调用闭包将其改成 7，最终画面为 `actual=7`。分析器明确要求该调用的写入摘要，禁止把最早读取的配置值 2 当成最终值。

11 项模板检查按分类达到预期：3 项生成符号模板，6 项明确未解析，2 项容量拒绝。模板的普通 Lua 输出与旧候选、原版 Lua 后端比较；未知分支、循环、函数返回、捕获单元写入及 C 包装参数映射没有被替换为空操作。**未解析被正确报告，只算诊断；符号模板本身也不算值投影或旧模组兼容通过。** 辅助函数的参数模板仍缺少调用者绑定。

捕获位置、指令和静态表达式只能提供身份与依赖结构线索。它们还没有证明原值的生产版本、查询的权威时点、动态调用实例或跨帧来源。所有 `bindings_verified`、`projection_allowed` 和缓存复用开关保持 false。

## 配额与交付

维持每个模型子进程 1000 万工作上限、5 秒超时、1 GiB 进程配额。正常读写计费规则未放宽；分析按读取字节、扫描指令及创建节点另计，通过时与原生工作量合计不超过 1000 万，并有独立 5 秒分析期限。

沿用原 1024 字段/单元、每消费者 1024 内部及 1024 外部记录、总读取条目 16384 的限制。可选模板每帧最多 128 个位置、64 份原型，每份 256 KiB、合计 512 KiB；分析最多 4096 个全局节点、64 层表达式。用 16 个真实回调的平衡表达式验证全局节点上限，避免仅限制单份原型而让总记录继续增长。

当前仅一个新构建目录，复用已有原版参考 EXE 和 Lua 库。较早结果及当前包含大量长键的详细结果均逐字节校验后无损压缩；保留精简摘要、二进制、生成源和链接符号。只删除本候选可再生的构建中间文件，没有复制游戏资源、启动游戏、触碰个人存档或新建研究 ZIP。

入口（项目根目录）：

```powershell
python -B authority/tools/verify_compact_reads.py
python -B authority/tools/run_compact_reads.py run --output <新的空结果目录>
python -B authority/tools/run_draw_plans.py run --output <另一个新的空结果目录>
```

重建先运行 `python -B authority/compact_read_runtime/prepare.py`，再用本机 Visual Studio 18 2026、Win32、Release 构建 `compact_read_runtime` 到 `build-compact-read`。等构建退出后再测试。未改动旧 `boundary_current.json` 的已封存基线；实验候选说明在版本化的 `compact_read_candidate_v1.json`，可更新的后续指针在 `boundary_next.json`。

下一步把模板源节点绑定到实际发生时的字段、upvalue 和查询版本，并用原 Lua 算法核对求值后的三个参数。接着补调用的返回/写入摘要、延迟条件和跨帧存储来源，再接回个人设置/普通 HUD 用途规则及主机贡献。当前没有运行真实 MCM/EID 初始化或画面验收，也不能声明联机修复已可用。
