# API 边界与初始化衔接：分步重构

目标保持：模组源码不修改；个人配置、按键与呈现独立；只有主机提交世界修改；相关奖励及其显示读取主机结果。沿用 `personal-settings-authority-hud-v1`，不以共同界面或逐模组适配降低要求。

## 第一步：初始化衔接底座（本轮实现与验收）

- 独立 Windows x86 命令行程序，直接编译固定官方 Lua 5.3.3 源码，不依赖全量追踪 DLL，也不改游戏 DLL。旧全量追踪器、清单和失败记录保留作离线工具。
- 同一私有 Lua 状态从初始化保留到回调；注册时保留真实函数 registry 引用。初始化获取的配置表、别名、嵌套闭包、共享 upvalue 和缓存 API 保持原 Lua 身份，不复制闭包或模拟私有变量。
- 元数据按需记录：函数/对象的上下文内身份、原型哈希、upvalue 单元，以及测试请求明确读取的字段。大表只登记身份，不遍历整个对象图。原生 API 在加载模组前安装，调用时检查当前角色与阶段，缓存函数不能绕过权限。
- 字段/upvalue 版本暂为“观察版本”：在指定观察点比较实际内容。不能检测观察点之间 A→B→A 的写入，不能用来证明未写入或缓存命中合法。下一步才加入精确写屏障和读取集合；禁止把观察版本冒充完整失效机制。
- 世界写入只允许主机权威阶段；个人上下文的随机/世界写入拒绝，查询读取明确的权威快照。配置写入独立研究存储，捕获绘制仅为隔离观察，不提交游戏或发布个人帧。
- 初始化与回调都用 1000 万工作单位、每个子进程 5 秒保护。工作单位新清单明确分项：Lua 每 64 条指令保守预付一块；API、编码和实际观察另计。该单位与旧全量追踪总量不同，不能用它的下降宣称同等算法加速；同时报告实测时间和字节。
- 同一 API 后端分别关闭/开启身份观察，比较普通 Lua 输出、配置、世界调用、错误与字符串字节。覆盖原始源码、字段别名、共享 upvalue、返回闭包、缓存 API、GC/移除/重新注册、保存重建和中途失败。

阶段出口：初始化到回调的身份与状态衔接通过，新增元数据不随无关大表字段数量增长，正常路径无完整图/证据审计文件。该出口不等于自动拆分混合回调通过。

## 第二步：精确读写集合与最小依赖

- 为已登记根添加可靠的字段/upvalue 写屏障，覆盖普通赋值、rawset、表库、闭包别名和原生返回；未知写入口拒绝。特别验证 A→B→A、删除重建、对象地址复用与 GC。
- 在真正消费配置、世界结果和绘制参数的位置记录实际读取；只失效受影响的消费者。API 缓存身份必须携带角色、上下文代次及真实原生调用身份。
- 为普通值经过算术、分支、字符串和闭包流向边界建立惰性表达式/静态摘要。不得只看参数、名字、顺序或最终结果配对；新增个人分支仍须复用既有反例验收。
- 不能证明的混合回调保持能力失败。第一步存活的 Lua 状态不是自动投影的证明，也不能跳过初始化来源问题。

## 第三步：事务、投影与真实初始化

- 在前两步证据成立后，接回主机贡献引用、菜单/普通 HUD 用途规则，以及完整失败恢复和去重；逐项复用原冻结反例，功能与安全拒绝分开。
- 通过有超时的短模型后，再用真实冻结 MCM/EID 进行初始化、菜单和绘制验证。完整证明仅按需进入离线工具；正常执行只保留当前决策的必要证书，不生成全量逐值历史。

本轮不启动游戏、不动个人存档、不测试通信。只建一个新构建目录；不复制模组/资源，不生成 ZIP，核验后移除本轮编译中间文件。
