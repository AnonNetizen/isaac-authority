# 最新运行时的无配额测量：2026-10-16

本轮按用户选择，同时测金币模型和冻结的真实 MCM/EID 入口。最新紧凑记录实现跑完有限压力样本；真实源码仍缺少游戏 API，无法得到完整初始化总量。没有把缺失接口替换成空对象，也没有启动游戏或写入个人存档。

## 方法

测量程序从已封存的冻结模块候选派生，使用 Windows x86、同一份修复后的 Lua 静态库和独立 ABI `ia-lua533-current-measure-1`。只在 `build-current-uncapped/source` 内取消工作量、时间、1 GiB 进程提交、消费者/字段/键、源观察、绘制快照及冻结模块文件容量配额。固定栈快照改为实际栈数量的动态数组。逐文件来源和 SHA256 见该构建下的 `derivation.json`。

仍受 x86 地址空间、系统可用内存、Lua 本身的表示范围及 uint64 计数范围约束。保留源码哈希、路径、类型、未知操作和主机写入权限检查；这些检查决定执行结果的可信范围。没有开启旧全量追踪，也没有运行表达式投影验证器。

正式候选的 1000 万工作上限、5 秒超时和 1 GiB 配额保持不变。7 个正式限额对照仍按原限制退出。专门使用无限循环验证工作配额的 `module-work-cap` 被明确排除；取消限额后该案例没有可测的正常终点。

## 实测结果

73 项独立尝试及 7 个正式对照的测量流程约 17.64 秒，包含子进程启动、等待、结果比较及结束审计，不包含编译。67 项执行至原生入口正常结束；另有 2 项预期的哈希/路径拒绝、1 项真实 FilepathHelper 失败及 3 项真实模组初始化失败。73 项均取得结构化结果，且与各自历史结果或本轮明确预期一致。**这不是 73 项功能兼容通过。**

| 有限压力样本 | 工作量 | 原生秒数 | 私有提交峰值 MiB |
|---|---:|---:|---:|
| 百万次读取，开启值观察 | 23,000,452 | 1.1713 | 2.141 |
| 同源码，仅关闭可选值观察 | 14,000,369 | 0.5385 | 2.137 |
| 20,000 字段读取 | 620,375 | 0.0728 | 9.137 |
| 8192 字节键的 A→B→A | 3,352 | 0.0112 | 2.441 |
| 40 层调用栈 | 3,131 | 0.0102 | 2.145 |
| 257 次绘制捕获 | 11,635 | 0.0529 | 6.449 |

百万读取沿用上次测量的同一个冻结 Lua 文件，上次开启观察约 50.02 秒，本次约 1.17 秒；工作量均为 23,000,452，世界、私有存储和绘制输出一致。两次不是统计重复，不能把比值作为稳定性能保证。本次开关观察的同源码输出也一致，开启观察约为关闭时的 2.18 倍耗时。

该样本累计只创建 9 条观察记录，原地更新 999,999 次、复用 1,999,998 次；结束仍保留 9 条、序列化负载 2005 字节，热路径 JSON 构造和序列化均为零。它消除了这个样本中原先每次读取产生短命记录的开销，不证明所有长期会话内存恒定。

原 24 个紧凑值案例均执行结束，原负载容量案例开放后完整保存两条各 65536 字节文本，252 项编码长度检查一致。未解析的调用摘要、分支及用途证明仍保留原来的未通过状态。冻结模块的 37 项有限模型执行、2 项明确拒绝与原记录一致；真实 FilepathHelper 仍失败。拒绝案例内的恢复行为也与原记录一致。

这三个入口没有因资源限额结束，但缺失的 API 提前截断了执行，不能据此估算完整初始化需要多少预算。旧 UI 框架曾经初始化过的结果也不能替代新架构的验收。

下一步仍是先接入有对象寿命、字段版本和明确资源/场景契约的 `Sprite`、`Game` 后端，再逐个处理真实源码暴露的未支持入口。当前不进入真实渲染、菜单导航或通信。旧模组不改、个人配置独立、奖励跟随主机继续作为完整目标，当前模型未证明全部满足。
