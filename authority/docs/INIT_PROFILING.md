# 初始化测量与优化计划

## 约束

只运行独立 Windows x86 命令行；10000000 工作上限、每次 5 秒超时。冻结 MCM/EID 和资源、旧候选、个人存档保持不变。维持个人配置独立及权威奖励规则。仅一个新构建目录，不生成 ZIP 或复制模组。

## 顺序

1. 在来源标记、聚合、字段索引、失效传播、值图装配/读取、CFG、审计编码/IO 和预算账本入口设置低成本活动标签。固定大小共享页保存采样计数和定期账本快照；不输出逐指令日志，不回读历史审计。
2. 先对小模型比较采样开/关的结果、来源、完整证明、审计及预算；记录计时开销。采样为墙钟归因，含等待；不冒充精确 CPU 耗时。超时前快照不是完整初始化总量。
3. MCM、EID、组合各一次有界测量，取得超时前最后的账本、样本数、活动类别和调用次数。保留固定数量进度点，不保留新的巨量完整审计副本。
4. 根据实测再选来源标记/聚合中的一个可证明优化点。不能删除依赖、跳过未登记副作用或把未知路径当作纯界面。若该路径并非主要热点，明确区分局部收益和整体瓶颈。
5. 候选先通过冻结模型回归、来源 oracle、双视图、审计重建和有界性能对照，再作相同 5 秒真实初始化尝试。不得以延长超时或扩大预算取得通过。

## 阶段出口

报告分别给出正确性、采样可信度、局部优化和真实初始化的结论。未完成初始化时不报告完整总工作量；审计/节点等其他原有限制触发时同样保留失败结论。

## 已测得的热点与实施顺序

首轮三个 5 秒窗口均停在首个模组加载阶段，最后完整账本为 3081385 / 3332781 / 3295887，未触发 1000 万工作限制。这只是超时前的部分进度。各窗口约 291–299 个样本，实际采样间隔约 15.6 ms；活动标签给出互斥墙钟归因，嵌套调用记在最内层，不能把 `source_mark` 自身占比误读为整棵标记调用树占比。

审计文件操作约占 33%–35%，节点重建为 JSON 约占 16%–22%。细分测量进一步确认，其中来源/存在性证明的节点重建占整个窗口约 8.5%–11.7%。聚合本体、来源集合合并和字段索引的独占样本很少，本轮没有证据支持扩大这些缓存或忽略字段/upvalue 写入。

第一步使用 `Graph::proof_node` 的只读借用直接检查操作类型和依赖边，仅 MOVE、GETUPVAL、native_return 等需要时才解码 detail。保留原有按不可变生产者编号的缓存、先于命中检查的深度限制、活跃节点检查和缺失节点拒绝。借用不跨修改或回调保存，不增加引用根。原算法保留为诊断路径；短测逐个新证明与原 JSON 算法对照。审计编码和证据格式不变。

第一步的完整 37 项短测通过，其中 27 项功能案例、10 项拒绝诊断；拒绝诊断不计成功能兼容。较大的固定短基准工作量 1078805 → 1057031，两个样本耗时约 1.55 秒 → 1.45 秒。真实初始化各做一次旧、新路径 5 秒对照，来源证明的完整节点解码调用降为 0，但三项仍超时；完成指令多约 3%–5%，不是初始化通过。

第二步针对标记、聚合共用的证据描述索引：旧有序映射反复扫描 JSON 长前缀，首轮该比较及其扫描占约 34–42 万工作单位。候选使用逐块计费的哈希桶加完整字符串相等检查，保持原始描述编号、内容和使用顺序。哈希仅作检索，绝不作依赖或权威匹配证明。保留原有 65536 个描述和 64 MiB 编码限制、全局内存限制、故障锁存及事务边界。附加强制哈希碰撞测试；实际收益须由相同冻结工作负载验证。
