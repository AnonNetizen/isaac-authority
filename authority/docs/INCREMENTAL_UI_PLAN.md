# 字段与 upvalue 增量追踪计划

本候选只运行独立 Windows x86 Lua 5.3.3，不启动游戏。冻结模组文件原样执行；保持 `personal-settings-authority-hud-v1`、个人配置独立、奖励跟随主机。旧候选及清单保留。

2026-10-11：用户将后续研究工作上限明确调整为 500 万。下文 200 万数字记录此前基线和当时门槛；后续新候选使用 500 万，其他限制与逐步验收顺序不变。提高上限的效果通过独立清单和真实耗时记录判断，不据此宣称算法优化、初始化成功或联机已可用。

## 顺序与门槛

1. 建立独立 `ui-incremental` 候选，ABI `ia-lua533-slice3-ui-incremental-1`。表字段采用带类型的键，结构独立记版本；闭包连接到实际 upvalue 身份，开闭状态和地址搬迁不作为新值。缓存包含根版本和已访问结构的深度、遍历成本。只在版本一致时命中。
2. 覆盖 Lua 快速/慢速表写入、rawset、整数写入、原生 insert/remove/sort、SETLIST；捕获 SETUPVAL、开放 upvalue 的栈赋值、C API setupvalue/join、关闭及栈搬迁。修改沿反向依赖边失效；别名共享对象身份。陈旧边允许保守失效，禁止漏失效。未登记操作仍拒绝。对象身份保存在对象内，GC 重用地址不能继承旧缓存。
3. 保留全量算法作为可开启的只读验证 oracle。小案例逐次比较每个标记后的字段/upvalue 来源和聚合来源，另外与原始 Lua 对照实际返回值、字节、表和错误。验证模式的额外工作也入账，不以免费 oracle 帮助实际初始化。
4. 运行真实冻结 MCM/EID 和 J460；每个上下文最多 200 万工作单位，32 路径、8 条件及既有结构限制不变。键处理、版本维护、失效、缓存查询与报告证据构建计费。超限是门槛失败。
5. 分离缓存证据与实际执行图。记录字段/upvalue 版本、失效原因、复用依据及完整旧图；不改变 Lua pairs/next 顺序，不通过删除编号制造一致性。只有逐字段来源与生产者依据一致才能报告稳定。实际执行顺序或生产者不同必须保留差异，不能强行合并为相同贡献。

## 验证范围

覆盖新增/覆盖/删除字段、结构迁移、别名、环、闭包共享与关闭、开放 upvalue 写入、缓存函数、动态加载、原生表变更、元方法、失败后禁止续跑。先小案例，再真实初始化，再重复及可校验交付。旧 166 项按原 DLL/模式回归；安全拒绝与功能兼容分开统计。

初始化或证据门槛未通过时停止于命令行结论；绘制捕获、菜单导航、真正菜单用途边界、渲染和通信不提前接入。增量缓存不会推断作者意图，也不会把来源未知当作界面计算。

## 测量后的下一步

首版完整根缓存的来源对照通过，但真实 6 项初始化仍超预算。批处理将首轮 MCM 约 67.8 万次重复父级失效减少到数千次；实际瓶颈变为再次扫描根内所有字段。不能据此扩大预算。

下一候选应把反向边改为“父对象 + 字段或 upvalue 索引”，为每个已完成的来源传播保存字段版本、子依赖版本和 upvalue 版本检查点。实际字段写入及子依赖变化只入队对应字段，闭包只重算改变的 upvalue；结构变动、别名替换和新循环需重新证明完整性及既有深度/遍历限制，不能沿用局部循环缓存。按“标量字段覆盖 → 共享子表 → upvalue → 新增/删除结构 → 循环”逐步接受全量 oracle，再进入同一真实清单。

证据编号方面，已缓存稳定排序的元数据字段索引。初版按 Lua 栈范围排除失效临时寄存器仍不充分，0.1.2 解压复现暴露了拼接后的失效值。新版本按需分析从条件位置到读取、覆盖或退出的控制流，并检查逃逸开放 upvalue；该分析、动态检查和查询缓存都计费。15 项模型的完整生产者图及缓存事件重复一致，原不稳定的表扩容案例另运行 20 次一致；预算账本受实际 Lua 表布局影响而保留差异。失败包和原报告保留。真实初始化失败前缀与实际 `pairs` 执行顺序仍不能声明稳定，更不能用重编号将不同生产者对应成一个权威贡献。

## 下一候选的逐步验收

1. **标量字段。** 反向边记录父对象与字段键，写入仅登记该字段。每次已完成传播记录来源覆盖、字段版本与检查点；复用必须证明所有未处理字段自检查点以来未失效。先验证覆盖、别名与删除后重建，不依赖字段名推断用途。
2. **共享子表。** 子对象版本变化向每条实际父字段边传播。移除旧关联时不能使共享别名漏失效；旧边若保守保留，只能造成额外工作，不能让非可达对象获得来源。先对照多父对象、嵌套表及重绑定。
3. **upvalue。** 以实际 upvalue 身份与字段版本为检查点，区分闭包中的引用索引和共享存储。覆盖开放栈写入、关闭、栈搬迁、setupvalue/join 与 C closure 写入；内存地址变化不等于值变化。
4. **结构和循环。** 新增、删除、弱引用或环改变可达性时重新证明完整性。不能使用局部循环结果，也不能因为跳过旧字段而绕过原有深度与遍历上限。无法提供完整证据时回退到计费的完整遍历或明确拒绝。
5. **真实门槛。** 每一步先过同一 VM 的全量来源 oracle 与普通 Lua 对照，再检查完整模型图、版本证据和搬迁复现。仅以上步骤通过后重跑真实 20 项清单；6 个 MCM/EID 功能项全部满足预算和契约，才推进绘制捕获与输入导航。功能拒绝仍算失败。

下一候选需要记录脏字段的入队、来源覆盖的检查点、字段/upvalue 消费的实际版本及复用证明。所有维护、证据构建与失败恢复成本继续纳入 200 万账本；不以减少报告字段、改变原冻结模组或放宽预算获取通过。
