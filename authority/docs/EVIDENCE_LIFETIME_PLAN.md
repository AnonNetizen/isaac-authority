# 常驻证据生命周期重构

范围：独立 Windows x86 命令行研究；每次执行最多 1000 万工作单位、5 秒。保留旧候选和失败记录。冻结模组源码、个人配置视图和主机奖励投影规则不变，不启动游戏、不写个人存档。

1. 使用记录与站点历史只追加到现有审计流。执行端保留单调流水号和最后一次已接受的使用，不保留历史向量。完成证明继续使用活跃 memo 的对象版本、覆盖版本与完成事件号。访问非最后一次历史使用明确拒绝。
2. 描述是可丢弃的证据编码缓存，不是世界计算结果。采用至多 8 MiB、8192 项的 LRU；键作完整字节比较，哈希只选桶。描述编号永不复用。淘汰后旧 memo 的编码提示失效，重新生成同一逻辑事件；不得把缺失提示当作有效证明，不读回审计文件。
3. 审计继续记录每次逻辑使用、完整定义和原编号。完整历史由命令行诊断器在执行结束后独立重建。描述重新编码会改变物理编号，因此另行比较展开后的完整逻辑事件序列；观察值、来源、值图、世界视图及分支证明仍逐项比较。缓存编码差异不得隐藏成语义通过。
4. 用同一新 DLL 的保留历史对照模式核对短输入，覆盖重复使用、唯一描述流、淘汰/再生成、陈旧编号、哈希冲突、记录追加失败、写盘失败及超预算。对照仅用于短测，也受 1000 万/5 秒限制。检查当前/峰值常驻字节与最大申请，证明内存不随使用数增加，没有历史向量扩容。
5. 通过存储门槛后，原 37 项短模型按原源码原预期回归，核对审计、普通 Lua 结果、双视图、失效恢复及重复执行。通过后各做一次 MCM/EID/组合的 5 秒初始化，不把超时或安全拒绝算兼容通过。

所有哈希、比较、编码、淘汰和诊断成本按实际工作登记。原 512 MiB DLL 堆、1 GiB 子进程和审计配额不扩大。只新增一份小型派生源码和构建；审计核对后删除，不复制模组/资源、不创建 ZIP。

本轮只解决使用历史、描述及站点编码的驻留；活跃值图、对象/字段/upvalue、来源集合与其他索引仍分别受既有上限约束，不能据此宣称整个运行时已实现恒定内存或真实菜单已通过。
