# 随机奖励引用与同路径分支证明：2026-10-17

独立 Windows x86 命令行 ABI `ia-lua533-reward-timeline-1` 已接上模型随机状态、结果来源和事务重建。它尚不能作为游戏联机补丁使用。游戏、个人存档和已封存的父候选未改动。

## 本轮实现

主机的 `math.random` 和 `math.randomseed` 在权威帧内生成有身份的世界操作。记录保留参数来源、调用上下文、操作前后状态、随机生成器哈希和返回值。个人环境只引用唯一匹配记录，不推进或重置共享生成器。随机结果具有独立的 `authority-result` 身份，随后经过字段、upvalue、算术和字符串消费。一个已产生的结果用于两个世界操作或多处绘制时，仍是同一个结果，不能把消费者当成新的随机生产者。

模型提供者固定为 `coin-model-mt19937-v1`，原版 Lua 对照和研究 Lua 使用相同的确定性模型 API 后端。整数随机支持一参数、二参数和 int32 范围，零参数返回 `[0,1)` 的 double。整数边界按 Lua 5.3.3 的 `lua_tointegerx` 接受可精确转换的浮点数和数值字符串。种子暂限一个 uint32 整数参数；零返回值另行验收。这不是原生 J460、Isaac RNG 对象、平台 C 随机算法或完整 Lua 随机 API 等价性证明。时间源和其他未登记来源继续拒绝。

普通 HUD 的选择仍在绘制消费处进行。已证明来自权威结果及常量的表达式保留权威来源，不因多个金币消费者产生虚假的多候选。混合个人设置的表达式保留个人普通计算；其 HUD 游戏视图使用唯一主机贡献，个人配置不被覆盖。没有按文字、字段名、相同数值或调用顺序猜奖励。

分支现在可以证明普通值和游戏视图得出相同的比较结果，包括已引用随机奖励、以及参数不同但布尔结果相同的设置比较。证明记录操作数、比较和选择。两种视图选择不同分支时仍明确拒绝，未实现独立的呈现分支上下文，不会靠改变本次 Lua 执行的条件而跳过个人设置或保存。

个人额外绘制中的已登记只读查询，可在本帧全部权威操作已经唯一匹配后，引用明确的最后操作边界。证明记录已匹配操作及状态编号；出现后续未匹配修改仍拒绝整帧。修改前、操作中间或其他无法定位的查询不能默认读最终状态。显式绑定旧帧的查询与随机结果不回退当前世界，也不倒退后来帧的生成器。

失败通过初始上下文与已接受历史重建，恢复模型世界、生成器、个人 upvalue、私有变量、配置和绘制队列；本帧记录不会发布。重复帧返回缓存；同编号不同负载拒绝。计数表示重建后的逻辑调用次数，不能用来声称恢复时没有重新执行已接受的主机历史。

## 验收证据

- 冻结 `research/reward_timeline/suite-v5.json` 共 26 项，私有运行时各运行两次：18 项功能或恢复通过，8 项拒绝诊断正确。拒绝项仍是能力边界。

- 在保存、私有状态和绘制后注入失败；另在主机随机、世界修改及保存后注入失败。直接检查恢复的闭包值、保存、全局、GetData、绘制、生成器哈希及模型效果，与原版 Lua 主机控制比较。
- 原两个模型门槛复用原源码、配置、步骤和预期，仅添加既有帧协议关系，通过新 ABI 回归。原 World View 35 项原清单和原预期通过，其中仍含 11 项预期拒绝。

所有子进程保持 1000 万工作单位、5 秒、1 GiB 私有内存保护。新增来源证明和随机状态编码计入工作账本。快照、来源图和证明沿用固定容量；未扩大预算、开启初始化全量追踪或回读审计历史。
