# 执行投影研究 slice-0.1.0

这是独立 Windows x86 金币模型候选，通用隔离门槛仍未通过，不能用于修复真实游戏联机。旧模组源码保持原样；个人新增随机分支和三个循环案例可以引用主机最终奖励，同时保留个人界面修改。新增反例仍暴露未解决的控制流、状态时点和用途歧义。正确拒绝只表示诊断有效。

## 运行与撤销

本轮不启动或附加游戏、不安装游戏钩子、不替换游戏 DLL、不写个人存档或模组配置文件。两套配置只保存在模型上下文里；结束命令行进程即可撤销。游戏目录用于校验枚举、历史冻结模组源码及运行原有离线回归。

源码目录构建：

```powershell
.\tools\build.ps1 -TraceResearch -SliceResearch -BuildDirectory build-slice `
  -RuntimeOutputDirectory build-slice-release/Release
$env:PYTHONPATH='本地 lupa 2.6 所在目录'
py -3 .\tools\run_slice_research.py --binary-dir .\build-slice-release\Release `
  --game 'J460 游戏目录' --regression-lua 'J460 游戏目录\Lua5.3.3r.dll' `
  --output-dir .\reports\slice-new-run
```

研究包解压后的入口：

```powershell
# Python 3.12；原有 Python 回归使用 lupa 2.6。
py -3 -m pip install lupa==2.6
py -3 .\source\tools\run_slice_research.py --binary-dir .\bin `
  --game 'J460 游戏目录' --regression-lua 'J460 游戏目录\Lua5.3.3r.dll' `
  --output-dir .\runs\slice-001
```

输出目录必须尚不存在。执行顺序为：Lua 参考执行与图检查、投影功能检查、历史追踪检查、三份清单分别完整运行两次、原有离线回归、运行前后源码与二进制哈希比对。`validation.json` 保存结论和二进制哈希；`cases/` 保存逐例输出、依赖图、权威引用、首个拒绝入口、恢复和去重结果。完整计数以该报告为准。

直接运行器为 `authority-slice-research.exe --suite DLL SHA256 GAME SOURCE MANIFEST`，新清单为 `research/slice_suite.json`，案例使用 `mode=slice`。入口检查私有 `ia-lua533-slice-1` ABI；历史追踪 DLL、原生根对象和游戏中的批量入口均拒绝该模式。两个私有运行时与游戏 Lua 的状态不能混用。

## 值版本与呈现引用

官方 [Lua 5.3.3 压缩包](https://www.lua.org/ftp/lua-5.3.3.tar.gz) 固定为 SHA256 `5113c06884f7de453ce57702abaac1d618307f33f6789fa870e87a59d772aca2`。74 份原始文件继续按固定清单校验；插桩仅生成在构建目录。Lua 许可保留在官方源码中。历史 `trace` 实现和未修改参考 DLL 同时保留。

私有 `TValue` 增加值版本编号。图记录实际值或原始字符串字节、生产指令、数据及控制依赖、表字段和结构版本、共享 upvalue、返回值及原生调用摘要。Lua 表和闭包使用上下文内对象编号，地址不进入报告。字段覆盖的前一版本作为历史关联记录，不被冒充成当前值的数据生产者。

字节码 CFG 记录分支后支配位置、循环和潜在定义；未执行的寄存器、upvalue 定义有保守控制依赖。未能解析的静态调用或堆对象目标保留为明确的未解析记录，不构成“纯界面”证明。该图仍是有限覆盖的研究图，不是完备静态分析。实际遇到未知原生操作、无覆盖的延迟值运算或预算超限时失败。

配置编码保留字段映射；映射随字符串值版本传递，并随模型保存/加载恢复，不按 JSON 字节相等合并两个生产者。解码后恢复对应字段依赖，避免整张配置表继承某个世界字段的用途。与内部描述符同名的普通 JSON 字段仍是普通数据。

主机执行一次，记录世界调用、参数版本、结果与前后状态。个人环境执行自己的界面和配置操作，随机调用产生未求值表达式，算术和拼接可继续形成表达式。个人环境不运行这次随机计算，也没有随机返回值。

当表达式到达唯一对应的世界贡献消费位置时，呈现端引用该主机贡献的实际参数，例如主机最终 `AddCoins` 的奖励。记录包含双方源码/调用上下文、权威事件、权威值版本和个人表达式编号。循环案例绑定最终贡献，而不是删掉循环上限后去匹配第一条随机调用。多个显示位置可引用已产生的主机结果，不再次执行世界操作。

查询仍要求唯一对应状态时点和参数。直接个人设置值同时被用作世界参数和显示内容时，若数值不同且无法判定显示用途，候选拒绝，不根据文字标签猜测。延迟世界结果在贡献绑定前控制个人分支、同一表达式对应不同权威消费者、个人新增查询没有状态时点，也拒绝。

## 验收与结论

历史 13 项清单与 31 项清单保持原样和原哈希，分别运行；其中真实 MCM/EID 初始化项在独立环境中继续标为未验证。新清单独立冻结，使用相同历史反例源码和新增反例。

| 案例 | 预期验收 |
|---|---|
| 修改前/后查询 | 两人显示 `0->1` |
| 个人新增不同范围或同范围随机计算 | 主机实际奖励保持一致，个人位置、选项、保存和额外界面命令保留 |
| 数值循环次数不同 | 显示最终奖励 88，不能显示第一条随机值 87 |
| 通用迭代与尾调用提前返回 | 分别显示最终奖励 90 和实际提前返回奖励 87 |
| 同行、辅助函数、缓存、尾调用、动态源码 | 不把主机废弃的随机值当奖励 |
| 混合字段、别名、闭包和配置重载 | 个人设置独立，世界字段引用关系保留 |
| 相同 JSON 字节、不同生产者 | 两个字段的世界/常量依赖仍可区分，普通同名标记字段不变 |
| 未绑定结果控制分支 | 明确拒绝；修改后的配置、私有状态和绘制队列恢复 |
| 新增查询缺少权威时点 | 明确拒绝并恢复 |
| 多个权威消费者、设置/奖励用途歧义 | 明确拒绝，不计兼容通过 |
| 重复帧与错误功能预期 | 不再次执行或保存；拒绝帧恢复完整检查点 |

候选仍未满足通用旧模组隔离要求。有限表达式投影能解决旧候选的五个失败案例，但没有实现通用控制流双视图求值，也没有解决所有查询时点和显示用途歧义。因此不进入真实菜单/HUD、原生世界接管、通信或个人解锁。

恢复采用重建私有上下文并重放已接受历史，比较完整输出；范围包括模型世界、RNG、配置、私有变量、图、投影绑定和绘制队列。代码目录按源码哈希和函数路径登记，避免 Lua 回收原型后产生地址相关的重复记录。诊断时间和报告体积属于离线研究成本，不能用于推断游戏帧耗时、带宽或联机性能。

跨帧配置另有八帧检查：每帧界面中的 `previous` 必须等于上一帧主机奖励，保存值必须等于本帧奖励，个人位置修改继续保留。检查要求这八帧出现不同奖励，防止相等数值掩盖错误引用。

## 边界与历史记录

尚未支持任意 userdata、协程、弱表/终结器及原生副作用。私有延迟类型只支持当前登记的运算和受控边界；在比较、循环条件或未支持原生函数中使用时明确失败。图、CFG、加载源码、遍历深度、模型历史和指令均有预算限制。框架的预算钩子注册表写入作为可信内部操作单独记录；模组不能借此获得线程或修改该钩子。

当前证据属于 `reports/current` 中记载的二进制。开发阶段失败、初版冻结清单、上一轮追踪失败以及旧 J460 证据分别保留；它们只能认证各自记载的哈希。不同解压目录的诊断路径可以不同，解压复现仍须在自己的目录内通过完整重复输出检查和功能断言。

本轮没有退出游戏或执行退出后的存档审计；不把它们写成已经验证。真实游戏、双机连续 30 分钟、个人进度和模组资源重放仍属于后续工作。
