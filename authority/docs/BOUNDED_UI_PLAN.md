# J460 大函数有界追踪计划

候选独立于 Slice3 UI 1，ABI 为 `ia-lua533-slice3-ui-bounded-1`。原源码、DLL、清单、报告和研究包保留。只在命令行运行冻结源码，不启动游戏。

1. 将按指令保存的后支配集合替换为基本块 CFG、反向遍历次序和直接后支配树。连续代码用区间表示，逐指令仍保留精确合流位置。4,096 改为基本块结构上限（出口另外占一个节点），不是扩大旧平方矩阵。存储为 O(指令数 + 边数 + 块数)，固定点和树链求交的每一步计费；复杂结构仍可能耗尽预算。
2. 先用独立测试比较旧集合算法和新算法的所有指令合流点，覆盖分支、循环、不可达代码、跳过指令和多出口。不能到达出口的块明确拒绝。循环的合流证据只对可终止路径成立；执行仍受工作预算约束。不得给未知块指定最终状态。
3. Trace 和值图共用每个私有上下文的不可变分析结果。不使用跨上下文免费缓存。解码、建图、后支配求交、结果消费、静态分支扫描计入统一 2,000,000 工作单位，缓存读取与复制也计费。源码读取按 64 字节块计费，解析按词法 token 和编译发射指令计费；执行、值节点和依赖传播另外计费。32 路径、8 条未解析条件、原对象/节点/原型/分支区域上限保留。计费单位不是 CPU 纳秒，原生函数深度行为仍由已登记契约及资源上限约束。
4. 接入新的私有 DLL，并在结构拒绝和预算拒绝时返回受保护的错误。对照普通 Lua 的结果、字符串字节、表及错误行为；验证大直线函数、复杂结构拒绝、解析预算、重复上下文成本、分支依赖、缓存函数和动态加载。冻结新清单。
5. 再运行真实 J460 枚举、MCM/EID 初始化与注册清单，两次比较全部证据。若新门槛失败，记录下一失败入口，不放宽预算、不跳过追踪、不开始绘制捕获或菜单导航。

保留统一用途规则 `personal-settings-authority-hud-v1`：旧模组不修改、配置和个人输入独立、世界贡献与相关 HUD 跟随主机。本次控制流工作本身不证明真实菜单用途或奖励隔离已经接通。
