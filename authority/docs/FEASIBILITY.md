# 主机权威联机研究记录（2026-10-09 至 2026-10-10）

**结论：当前方案未通过首阶段的通用模组与可玩联机验收。** 已交付可运行的观察器和通信研究代码，但完整主机权威联机未完成，不能解决现有 desync，也不能宣称任意旧模组可兼容。单纯捕获主机绘制命令不能满足“每名玩家保留自己的界面、按键、配置”这一关键要求；把旧模组渲染回调重新执行一遍也不能保证世界只更新一次。这是当前路径的失败结论，不是证明所有引擎隔离或虚拟机隔离方案都不可能。

验收范围如下。通过一行不代表其所在整个功能已经完成。

最新独立 [执行依赖研究](EXECUTION_DEPENDENCIES.md) 修复了金币模型查询时序，并在同一行、共用函数、缓存函数、尾调用及动态源码案例中区分部分随机调用用途。个人分支新增返回值调用和循环上下文等 5 个新模式案例仍无法满足通用要求，候选门槛失败。它不启动游戏，不替换 Lua DLL，未接入真实菜单/HUD、原生世界或通信。当前研究包的复测证据与下述历史 J460 二进制分别记录。

0.8.0 的 [批量验收](RUNTIME_SUITE.md) 已实现 strict 对照和个人呈现候选，并在 J460 一次附加中复现全部 13 个预期结果、确认钩子撤销。金币模型接受配置影响写入数量等案例，但 4 个预期失败暴露读写交错和个人分支中的返回值调用歧义。通用门槛失败，因此不进入第三阶段的真实 MCM/EID 菜单/HUD。当前报告为 `reports/j460-runtime-suite.json`；下面各版本记录作为历史证据保留。

0.7.0 的 [私有初始化验收](PERSONAL_INITIALIZATION.md) 已通过未修改 MCM/EID 的中文与英文完整初始化和 EID 语言查询，0.8.0 整批实测再次通过。真实菜单/HUD、混合回调通用隔离及原生世界仍未通过；下面各版本记录按历史时间保留。游戏退出及退出后的存档审计另列为未验证，不阻塞研究包整理。

0.6.0 的 [动画与松散资源接入](RESOURCE_ANIMATION.md) 在 J460 中通过 28 项资源检查，未修改 MCM 能在一份私有 Lua 环境完整初始化，EID 仍停在基础道具资源。194 项本地检查与 7 项原生模型检查通过。资源能力扩展和 MCM 初始化不代表真实菜单、个人配置、原生世界接管或双机联机已经通过；总体失败结论不变。

0.3.0 的 [原生对象测试](OBJECT_BRIDGE.md) 在本机 J460 中通过。0.4.0 的 [原生模组运行环境](NATIVE_MOD_RUNTIME.md) 连接了私有回调、配置、输入和金币模型事务，真实字体与 Vector 闭包对象在失败后可重建。0.5.0 的 [资源与只读道具接入](ENGINE_API.md) 延后初始化，完成 8 项精灵、字体和元数据检查，7 项原生模型检查继续通过。MCM 已越过 Sprite.Load，停在 Sprite.SetFrame；EID 已越过 Isaac.GetItemConfig，停在未验证的图标资源。没有接管实体世界，也没有完成真实菜单和 HUD；总体验收仍未通过。

2026-10-10 增加了不依赖第二台电脑的主机侧影子 Lua 模型。18 项检查通过，原始反例能生成不同语言标签、位置和按键的两份界面，世界写入只提交主环境的一份；检查点重放能恢复有限模型中的私有变量。它尚未接入游戏。J460 枚举初始化缺少原生 BitSet128，EID 与配置菜单加载探测失败；个人配置影响世界写入的反例仍被拒绝，通用兼容门槛未通过。[单机隔离记录](ISOLATION.md) 给出源码、复现命令与具体边界。

研究前基线仍包含用户已有的主程序修改、中文补丁加载器和其他模组，不能称为原版净安装。主程序已测哈希为 `210cade2…ae4831`；原先保存的主程序备份哈希为 `7122ac28…3b3ea4f`，二者有既有差异。本次工作没有修改它们，也没有改动原有 desync 中断分支。研究最开始只撤销了已验证的激光模组实验补丁，没有清除其他已有功能。

较完整的真实记录是 `reports/j460-steam-v5.json`：日志跨度 308.937 秒，观察到 1 个房间、最多 24 个实体、49 个不同世界帧，以及 MCM 字体、MinimapAPI 和状态栏绘制。7 个真实 C 绘制入口被挂钩，记录到 209457 次观测调用，原生捕获错误计数为 0；停止时 Lua 回调发出了确认。这不是五分钟战斗验收，也不是原版双人游戏。菜单暂停使更新采样少于绘制采样。

这一旧版本记录也明确暴露了缺陷：40864 条字体命令不知道资源路径；51252 条字体命令缺少正确 RGBA 字段；缓存函数自检为 false。后续源码修复了 KColor 字段、原始文字字节、字体设置参数和自检的采集时机。最新编译的验证结果与对应二进制哈希见 `reports/validation.json`，最新真实运行结果单独记录；不能把旧运行的“零观测报错”视为正确界面重放。

最新运行 `reports/j460-final-ready.json` 的日志跨度 85.953 秒，记录 4998 个绘制帧、99361 次原生观测调用。采集到的字体颜色字段完整，文字改用 `text_hex`，缓存 C 入口自检为 true，原生观测错误为 0；停止后收到 Lua 确认，自己的 IAT 槽和 7 个钩子均已恢复或禁用。测试人在已进入的一局中打开配置菜单，更新处于暂停，故这轮没有新的世界帧；不能据此声称完成了战斗或跨房间。由于字体在晚注入前已加载，29982 条字体命令的资源路径仍未知，界面通用重放仍未通过。修复后的接入方式只完成了这次晚注入实测，自动启动后从头进入一局的端到端流程没有重复验证。

早期 v2 曾因将原生类方法替换成 Lua 函数，在配置菜单 Font.Load 路径崩溃。依据本机 `main.lua` 原生分派约束，之后改用真实 C 入口的同 ABI 钩子，保留原始方法字段。后续已测加载路径没有再出现这一崩溃。启动早期安装又曾出现仅初始化调用有记录、实际房间回调缺失的情况；这算测试失败，不能用非空的启动状态文件掩盖。单看公开 `_RunCallback` 的函数身份也未能接入真实分派，后续改用公开游戏帧和回调表作接入门槛，运行范围需以独立日志为准。

38 项原生检查涵盖 CBOR、有限值/大小/路径约束、实体关系、角色、序号、会话/清单、绘制帧对齐、逻辑断线恢复和进度事件去重；19 项 Lua 检查使用真实探针源码和 Lua 5.3 模拟 API，新增 18 项 Lua 检查验证独立的主机侧隔离模型。54000 帧的丢弃/重复测试是加速协议模拟，绝不能算真实运行 30 分钟。测试输入并未从第二台机器注入原生玩家。

`fixtures/legacy_chaos/main.lua` 是完整、未作网络适配的反例模组，未自动安装。两个 Lua 虚拟机使用不同的本地随机数与时间，执行一次更新及渲染后得到金币 2 与 7；同一虚拟机为第二名接收者再执行渲染，金币从 2 增为 3。主机私有语言与按键仍是 zh / L，客机自己的 en / M 及配置写入只有在另一个虚拟机中才能独立生效。它证明当前路径的缺口，不是当前原型已经隔离客机的证明。

Font / Sprite 的公共绘制绑定可以作为研究入口，却不是全局渲染流。字体可能在注入之前已加载，精灵还有覆盖动画、着色器、原生绘制等未采字段。当前预览跳过无法识别字体资源的命令，这一事实计入失败，不能以隐藏 UI 或关闭模组功能换取兼容通过。EID/MCM/内容模组也没有完成不同个人配置的双机验收。

性能数据仅有观测回调时间：v5 平均约 17.10 微秒、最大 1032 微秒。这不包含原始绘制、完整世界采集、CBOR、文件写入、网络或整帧耗时。约 224725 字节/秒的是日志 JSON 负载估算，并非实测网络带宽；该次原始日志约 70 MB，暂停菜单会产生大量重复绘制记录。当前可靠通道与无分片协议不适合作为最终高负载传输设计。

存档方面，原型没有原生进度提交代码，但正常游戏与既有模组会写文件。与研究前备份相比，Repentance+ 主存档、Steam 缓存及 13 个模组数据文件发生变化，已记录在 `reports/baseline-audit.json`；这是按文件哈希的记录，不能据此推断具体新增解锁或写入归因。当前文件已保留，没有自动回滚。激光代码恢复是预期变化，单独验证，不算异常进度变更。备份和原始日志保存在本机，研究包只带摘要。

继续实现需要先解决三项实质工作。第一，在已知 J460 验证原生 Game.Update、生命周期、输入、状态应用和渲染对象布局；目前公开签名扫描中 Update 无匹配、SaveState 有歧义，唯一匹配的其他函数也没有 ABI 验证。第二，将有限的影子 Lua 模型推进到原生 userdata、完整 API 与模组共享环境，证明个人私有变量、设置、键盘和 SaveData 语义可以通用隔离，又只提交一次世界写入；个人配置改变游戏逻辑仍是失败门槛。[Lua 5.3 手册](https://www.lua.org/manual/5.3/manual.html) 对函数、upvalue、userdata、C API 和状态的语义说明是隔离研究依据。第三，在两台机器上完成真实通信、原生世界恢复、个人进度与整场游戏验收。

这份研究因此给出的决策是：**当前“绘制捕获加简单玩家上下文”实现不可作为通用联机发布；完整主机权威架构仍有待实现和验证。** 包内提供的观察器可用于继续定位接入点和检验隔离方案，不能作为减少掉线的完成品。
