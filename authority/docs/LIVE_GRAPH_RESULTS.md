# 活跃值图与失效范围：实现和短测

2026-10-15。仅独立 Windows x86 命令行模型；游戏、模组安装目录和个人存档未修改。

## 本轮顺序

1. 将执行值图从审计缓存中分离，保留稳定生产者编号。诊断报告另行读取审计。
2. 按 Lua 活跃值、索引、闭包、userdata uservalue、活动控制条件与显式主机引用标记；完整数据和控制关系保守保留，安全点释放不可达节点。
3. 不可变字段/upvalue 值版本的证明缓存只删除死亡版本。区分 Lua 内存布局变化与内容变化，保持实际写入的失效。
4. 每步先短测，再进行整批检查。当前没有真实模组初始化或无上限测量。

## 执行与审计

- `live_graph_runtime/prepare.py` 建立私有 ABI `ia-lua533-execution-audit-2`。每个有效节点保留紧凑类型值和依赖，执行 `read()` 不访问 Journal。审计写入成功后才发布节点。
- 普通 Journal 读取默认拒绝；私有 CLI 仅在最终报告导出时开启诊断读取。诊断重建不会重新填充执行节点。
- 需要的节点不存在时，报 `Live producer unavailable; audit fallback forbidden`。不能通过重新读历史掩盖引用根缺失。
- 回收根包括 Lua 值、字段当前版本、对象结构/整体来源、帧输入和控制、原生调用暂存结构版本、守卫、HUD 使用、序列化形状及显式 host pin。沿全部记录的数据/控制关系保守追溯，不只沿显示表达式。
- 审计仍完整输出，稳定 ID 不复用；ID 槽位和审计偏移索引不回收，原 262144 节点上限不变。完整图回收仍标记为未完成，不能称整个进程内存恒定。
- 写审计仍是同步、受限输出；本步消除的是执行对历史文件的依赖，没有声称已实现异步审计或消除全部编码成本。

第二步结果：`reports/live-graph-step2-v1/result.json`，19 项功能和 8 项预期拒绝通过，23.04 秒，最大子进程 1.53 秒。保持与旧 Compact 完整逻辑证明对照、参考 Lua 结果对照、候选重复及独立审计重建。

## 字段和 upvalue：本轮实现到哪里

- `scoped_versions_runtime/prepare.py`：来源纯度和存在性证明以不可变生产者 ID 缓存。字段覆盖、upvalue 写入产生新 ID，不能复用旧值的证明。仍被引用的旧版本继续有效；安全点只删除已死亡版本的缓存。
- `semantic_versions_runtime/prepare.py`：表扩容仍丢弃原生槽位地址索引、增加布局 epoch，并按实际地址重建；不再因此递增内容证明版本。实际字段写入、删除、来源变化、共享 upvalue 写入及 join 的现有失效路径保留。
- 这不是任意消费者的读集合缓存。全对象遍历本来就依赖所有内容，实际内容变化仍向相关父对象传播；尚未实现更广泛的字段消费和 upvalue 消费读集合、重复通知合并或全局失效成本优化。

五阶段案例原样保存于 `research/scoped_version_fixtures/`：建立字段和共享闭包值 → 修改无关字段/upvalue → 修改相关值 → 删除/置 nil → 表扩容并恢复。检查值、来源、新版本及旧版本缓存命中，启用完整遍历 oracle。旧版本后续查询均在最外层命中两种证明缓存。

## 首轮失败与修复

`reports/scoped-versions-step3a-first` 和 v1 清单、源码、DLL 保留。

- 扩容测试两次运行的返回值、来源和完整值图相同，但缓存证据 `root_version` 不同。旧实现把哈希表内部布局搬迁算作语义内容修改；布局次数受内部哈希分布影响。第三步后续候选明确将两者分离。
- 两项 userdata 配置案例首次显示失败，原因是新通用测试驱动将原清单“每阶段相同期望”误读成“全部阶段列表”。v2 仅转换期望表示方式，原 Lua、数值和配置不变；失败报告保留。
- 新候选内容证明版本有意改变，因此不能要求与旧 Compact 的缓存版本号完全相等。基线要求普通结果、来源和完整值/控制图严格一致；新的缓存证明另以完整遍历 oracle、候选完整重复和独立审计重建检查。比较口径写入冻结 v2 清单，未静默放宽旧清单。
- 物理布局 epoch 仍保留在原始报告中，重复语义比较不将其当作可移植语义。字段索引树比较和 oracle 排序的工作计数仍有微小差异，逐案例报告，没有宣称工作计数完全稳定。

## 最终短测结果

`research/ui_scoped_versions_v2.json` 冻结 33 项：25 项功能兼容，8 项预期拒绝。报告 `reports/scoped-versions-step3b-v2/result.json`。

- 整批 27.21 秒，最大子进程 1.63 秒；每个子进程 5 秒、整批 90 秒超时。
- 每次工作上限 10000000，最大实际计费 1078793；没有改为无上限。原遍历、指令、节点、对象、64 MiB 证据、512 MiB 托管堆和 1 GiB 子进程限制保持。
- 所有成功返回报告的案例，执行历史读取均为 0。报告导出的历史读取单独统计。
- 全部 25 项功能案例启用完整遍历 oracle 并产生有效检查；候选两次功能/语义证明及审计字节重复一致。原始审计由独立解码器完整重建核对。
- 双视图原配置案例 amount=2/主机=1，以及反向交换均通过；userdata 中的两套配置也通过。个人语言、位置、金额和缓存文字保持个人值，HUD 金额与关联文字读取权威值。
- 七种已登记 userdata、userdata 键身份、跨帧显式保留引用、别名、共享闭包、循环、重新挂接、缓存证书损坏、失去活跃节点、审计损坏、写失败与工作超限均纳入对应功能或拒绝检查。安全拒绝不计为功能兼容。
