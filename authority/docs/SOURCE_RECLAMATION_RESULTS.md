# 活跃来源图回收：小规模通过，持续运行门槛仍失败

本轮仍是独立 Windows x86 金币模型，ABI 为 `ia-lua533-settings-value-1`。
新冻结清单通过 `source_reclamation=true` 启用回收；旧清单保留原模式。
旧模组源码、个人配置独立、奖励跟随主机的要求没有改变。
没有启动游戏、修改个人存档、扩大资源上限或建立 ZIP/资源副本。

## 实现

来源值采用单调递增、不复用的编号，以固定容量索引查找活跃节点。退休编号
再次读取会报错，后续分配不会让它指向另一个值。活跃图保持 4096 节点、
1 MiB；编号空间耗尽也会明确拒绝。启用回收后 `nodes` 数组的位置不再等于
编号减一，读取方必须依据每条记录的 `id` 建立索引。

只在已提交回调之外回收。读取 Lua 的实际已分配对象列表、线程栈、Lua/C
闭包 upvalue、表键和值、原型常量；同时保留已登记字段/upvalue 的当前版本、
向量构造参数及原生对象持有的最新来源。扫描包括尚未被 Lua 释放的垃圾，
属于保守根集合，不宣称已区分全部真正活对象。

扫描不运行 Lua GC、元方法或模组回调，也不改写 TValue。单次最多检查
262144 个值槽和 65536 个对象，扫描及标记工作进入原账本。来源不足或超限
会拒绝。沿已登记的语义边保留依赖，随后删除无用节点并裁剪相关缓存。
未知的活跃节点结构会拒绝；不会依赖审计历史文件重建被删节点。

`prior_storage_version` 等旧版本链仅作为审计身份保留，不能被解释成仍有效
的执行引用。报告明确标记审计链接可能引用已退休编号；图摘要也不等于完整
的离线依赖图。接受历史和其他组件仍未完成长期检查点/回收。

## 结果

| 清单 | 当前结果 |
|---|---|
| 原实际 MCM 功能 7 项，开启回收 | 全部重复通过 |
| 保存功能 7 项 | 全部重复通过，包含原第二次修改失败及新增连续六次修改 |
| 保存拒绝/恢复 7 项 | 按原预期拒绝并恢复，不计为功能兼容 |
| 引用根 4 项功能 | 表别名、闭包、缓存函数、延迟向量、显式 Lua GC、重建与重复消息通过 |
| 引用根 2 项安全检查 | 过期向量版本拒绝；退休编号不复用、缺根和未知结构标记失败保持原图 |
| 原 101 项回归 | 捕获 16、分支 20、API 35、存储 28、原两个门槛按原模式及原预期通过 |
| 原边界、标量原生契约及 MCM 捕获 | 各 2 项通过，包含既有拒绝诊断 |
| 连续十次菜单修改 | **失败：`Live value-object capacity exceeded`** |

六次修改用例两次约 2.37 / 2.33 秒、3222821 工作单位，结束私有提交约
38.3 / 39.1 MiB。普通/呈现活跃图结束为 1564 / 1570 节点，分别退休
9450 / 9587 个节点。正式保护仍为 1000 万工作单位、每子进程 5 秒、1 GiB Job。
上述内存为结束值，不是峰值曲线，也不证明实时帧性能。

十次修改失败表明向量/颜色登记表达到原有 1024 上限；它**不能证明全部登记
对象仍然被 Lua 使用**。当前保守扫描仍保留尚未释放对象，长期运行门槛因此
没有通过，不能用六次通过代替持续可用验收。

另做了一次明确改变执行调度的对照：在研究脚本中显式运行两套个人上下文的
Lua GC。该对照随后失败于 `Timeline provenance depth exceeded`。它只能帮助
定位下一步，不能算旧执行方式兼容通过；自动回收实现没有加入强制 Lua GC。

首轮引用根报告的跨次比较因 Lua 哈希表槽容量差异失败。实际配置、绘制、
来源编号和权威证明一致。现仅把累计扫描槽数和最后一次扫描槽数视为分配
诊断；原报告不改，重复消息在同一次运行中仍比较完整状态，确保没有新增
执行或回收。

## 复现与下一步

当前文件、二进制及结果哈希由 `reports/source-reclamation-progress.json`
记录，命令行为：

```powershell
python -B D:\Coding\ISAAC\authority\tools\verify_source_reclamation.py
```

前一 `settings-value-progress.json` 是旧未封存构建的检查点；二进制已经更新，
旧检查点不能校验当前构建。旧逐例报告及二进制哈希仍保留，当前以本轮检查点
为准。sealed 祖先没有改动。

下一步先区分原生对象登记表中的真活对象、等待 Lua GC 的对象和失效登记，
明确清理过程的 finalizer/弱引用行为，验证不会丢失仍被使用的 userdata 来源。
同时检查连续设置修改留下的表达式链，采用可信个人输入和字段版本边界时
必须保留普通个人计算及权威引用证明，不能随意截断来源或扩大深度限制。

之后仍需配置重载侧车、真实 EID 契约与完整菜单/HUD、游戏画面及原生模拟
接管、通信、断线恢复、各自解锁与双机连续验收。本候选整体持续运行门槛
失败，目标保持 active，不宣称任意旧模组兼容或可玩联机完成。
