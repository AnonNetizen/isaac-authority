# 执行依赖隔离研究 trace-0.1.0

当前候选仍未通过通用隔离门槛，不能作为联机修复发布。独立 Windows x86 运行时已实现，查询时序和部分同参数随机调用的错配已修复；个人分支新增返回值调用及循环上下文变化仍被拒绝。预期拒绝得到复现，只表示诊断正确。按计划保留旧 Presentation 对照，不进入真实 MCM/EID 菜单、HUD 重放或原生世界接管。

## 复现入口

无需启动游戏，不读取进程，不安装任何游戏钩子，不替换游戏 DLL。游戏目录仅用于校验冻结的枚举和旧模组源码；原来的 13 个案例完整保留，原生 MCM/EID 初始化项在独立环境中保持“未验证”。模型配置保存是上下文内的 JSON 数据，不写个人存档或模组数据文件。结束命令行进程即可撤销本轮运行。

```powershell
# 已解压研究包的根目录；Windows，Python 3.12，历史回归另需 lupa 2.6
py -3 -m pip install lupa==2.6
py -3 .\source\tools\run_trace_research.py `
  --binary-dir .\bin --game '完整 J460 游戏目录' `
  --regression-lua '完整 J460 游戏目录\Lua5.3.3r.dll' `
  --output-dir .\runs\trace-001
```

输出目录必须尚不存在，以免覆盖历史记录。脚本依次校验 74 份官方 Lua 源码及 x86 二进制，运行 VM 对照与功能检查，再运行两次冻结清单，要求完整输出一致。`validation.json` 记录源文件、运行时和可执行文件的 SHA256；`suite-1.json`、`suite-2.json` 保留整批结果；`cases/` 保存每个案例及拒绝前的依赖报告；`regression.json` 保存原有本地回归。计时是整个模型清单的墙钟时间，不是游戏帧耗时或网络性能。

当前验收复现 30 个案例的预期结果，0 个意外失败，1 个原生案例未验证；18 个新模式案例中，5 个仍是兼容失败。34 项 VM 对照与依赖检查、13 项功能与入口拒绝检查通过，原有 285 项本地回归通过。诊断通过没有改变候选门槛失败的结论。研究包中的 `reports/current` 是当前证据，源码工作目录对应 `reports/trace-final-release`。

源码工作目录的编译与运行：

```powershell
.\tools\build.ps1 -TraceResearch -BuildDirectory build-trace `
  -RuntimeOutputDirectory build-trace-release/Release
py -3 .\tools\run_trace_research.py --binary-dir .\build-trace-release\Release `
  --game '完整 J460 游戏目录' --regression-lua '完整 J460 游戏目录\Lua5.3.3r.dll' `
  --output-dir .\reports\trace-new-run
```

构建需要 VS 2026 的 MSVC x86 工具和 CMake。默认构建不打开研究运行时选项。直接运行器提供 `--suite DLL SHA256 GAME SOURCE MANIFEST` 和 `--evaluate DLL SHA256 SCRIPT trace|plain`；每次先校验 DLL 哈希。游戏中的 `--runtime-suite` 拒绝 `mode=trace`，且追踪上下文拒绝 `native_roots`，防止混用 ABI。

## 实现与证据

官方 [Lua 5.3.3 源码](https://www.lua.org/ftp/) 的压缩包固定为 SHA256 `5113c06884f7de453ce57702abaac1d618307f33f6789fa870e87a59d772aca2`。原始文件保存在 `third_party/lua533`，逐文件校验表为 `SOURCE.json`。`prepare_lua.py` 只在构建目录生成带插桩的副本；同次构建还生成未修改的 `ia_lua533_reference.dll`，用于比较普通 Lua 返回值。Lua 许可原文保留于 `src/lua.h` 和官方文档。

`TValue` 增加来源编号，表增加结构依赖字段。这改变了私有 VM ABI，两个新 DLL 的状态不能交叉使用，也不能与游戏 Lua 状态混用。来源集合经过寄存器赋值、算术、位运算、字符串拼接、表别名与键、结构变化、闭包/upvalue、Lua/C 调用、返回值和分支传播。分支用字节码控制流的后支配节点限定作用域；对未执行路径的潜在赋值保守标记，防止把“没有发生写入”当成无依赖。嵌套闭包状态也被标记。原生表排序、插入和移除合并参数及回调返回值来源。配置序列化由受控服务保留来源，保存后加载仍携带原来的世界及个人来源。

每次世界调用的证据包括源码 SHA256、函数原型路径、指令位置、父调用激活上下文、循环状态、分支条件、动态源码依赖、参数及来源、返回结果，以及调用前后的金币、帧、时间和 RNG 状态哈希。尾调用在覆盖栈帧之前保存上下文；进入框架函数后仍保留被丢弃的模组栈帧。它们是匹配证据，不是用途相同的语义证明，行号也不参与用途判断。

主机执行一次并生成权威记录。个人上下文使用自己的配置和输入，匹配只能向前消费一次对应事件。查询和返回值修改要求操作、位置/动态上下文、参数均一致，且只有一个未消费候选。查询返回该事件时点的结果，避免修改前查询读到最终状态。无返回值写入经过模型参数验证后记录并抑制，不提交个人世界修改。没有权威事件的返回值调用明确失败，不运行额外随机数，也不编造返回结果。

拒绝时重建私有上下文，再重放已接受历史，要求输出完整相同；恢复范围包括金币、RNG、私有变量、配置、Options、绘制队列及依赖记录。重复帧返回缓存输出，不再次执行或保存；同编号不同负载拒绝。案例的语义预期同时核对两人的文字、位置、模型世界及恢复结果，不仅检查世界没有第二次写入。

## 功能门槛

独立清单含 31 个案例：原有 13 个对照保持原样，18 个使用新模式。完整结果以 `reports/current/validation.json` 与逐例报告为准。

| 门槛 | 当前结果 | 含义 |
|---|---|---|
| 修改前查询、写入、修改后查询 | 通过模型案例 | 两人的界面均显示 `0->1`，查询分别对应前后状态 |
| 同参数、不同用途的随机调用 | 通过原反例及同一行、共用辅助函数、缓存函数、尾调用、动态加载案例 | 个人奖励使用主机奖励事件，没有误消费仅用于主机分支的随机结果 |
| 个人分支新增不同参数随机调用 | 拒绝，兼容失败 | 没有对应主机操作，无法满足返回值规则 |
| 个人分支新增相同参数随机调用 | 拒绝，兼容失败 | 已消费的主机结果不能再次使用 |
| 数值循环次数不同 | 拒绝，兼容失败 | 调用所处循环状态不能唯一对应 |
| 通用迭代器中的世界调用 | 拒绝，兼容失败 | 迭代状态可能含对象，尚无通用对应方法 |
| 尾调用丢弃循环栈帧 | 正确拒绝，兼容失败 | 保存循环上限后可检测上下文差异；仍不能证明应使用哪个权威操作 |
| 个人配置、按键、字符串保存再加载 | 通过模型案例 | 界面独立，来源保留，重复帧不再次保存 |
| 失败恢复、重复消息 | 通过模型检查 | 已接受状态和私有变量可重复恢复；预期拒绝未计为兼容通过 |
| 真实 MCM/EID 个人菜单与 HUD | 未验证 | 本轮没有调用真实游戏 API 或进行画面重放 |

结论只适用于该候选：增加执行来源和动态上下文能修复部分错配，但仍不能为主机没有执行的个人返回值调用提供符合规则的结果。5 个新模式案例仍是兼容失败，因此通用门槛失败。没有修改旧反例、逐模组打补丁、删除回调或隐藏界面来通过验收；也不能据此断言所有执行隔离方法都不可能。

## 能力边界及历史

这是有预算限制的保守追踪器，不是完备程序分析或任意旧模组兼容层。未知 C 函数、userdata、线程值、二进制代码、无法对应的通用迭代状态以及未覆盖的原生副作用明确拒绝。独立求值器中的原生 `math.random/randomseed` 与系统时间/环境调用未接入可恢复模型，明确拒绝；模组金币环境将随机数和时间接入权威服务，已有对应来源。调试器写入、文件加载、外部进程调用、垃圾收集控制、模组弱表和终结器等也拒绝。内存、指令、调用深度、尾调用上下文、来源集合和图遍历都有上限，超过即失败。来源集合可能过度传播而产生保守拒绝；有限测试不证明所有 Lua 操作和本机资源的任意组合正确。

本轮开发曾发现 setter 宏重复求值造成栈变化、`ipairs` 内部函数未登记、未执行分支漏记闭包状态、受保护错误未清除失效调用帧、尾调用进入框架后丢失来源栈及辅助函数激活计数范围过大。它们均加入对照/功能检查后修复。`reports/history/trace-suite-*.json` 与 `trace-development-history.json` 保留中间失败及其运行时哈希；当前报告只认证当前验证文件中的二进制。旧 `reports/history/j460-runtime-suite.json` 和其他 0.8.0 证据属于各自记录的历史 DLL，不能认证本次重编译的观察器。

可撤销的启动入口已经具备；本轮没有安装有效游戏钩子，也没有退出游戏或执行存档审计。原生世界接管、网络状态恢复、个人进度、双机连续 30 分钟验收继续保留为后续目标。真实菜单/HUD 接入按计划暂不推进。
