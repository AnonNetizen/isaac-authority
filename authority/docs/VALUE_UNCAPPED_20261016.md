# 当前值对象版本的独立无配额测量

按用户要求，金币模型和真实 MCM/EID 两部分均已尝试。49 个有限案例的测量过程约 14.06 秒，不含编译；取得 49 份结构化结果。45 个执行到正常进程结束，1 个因冻结哈希错误明确拒绝，3 个真实初始化因缺少 API 失败。部分正常结束的案例内部包含预期拒绝及恢复，**这些数量不表示任意模组兼容通过**。

## 临时测量设置

从当前 `build-value-objects/generated` 派生独立 Win32 构建，ABI `ia-lua533-value-measure-1`。仅该构建取消工作量、时间、进程提交、对象和记录容量、源码/存储字节、回调数量及调用栈观察容量配额。动态栈快照替代固定数组。共移除 39 处容量守卫，其他资源守卫变更及逐文件来源列于 `build-value-measurement/derivation.json`。

源码哈希、路径、类型、未知操作、来源证据和主机权限检查保留；未打开旧全量追踪。仍受 Windows x86 地址空间、系统内存、Lua 表示/栈限制及 uint64 计数范围约束。专门用于工作配额检查的无限循环案例没有正常终点，明确排除。正式程序的 1000 万、5 秒和 1 GiB 上限及二进制保持不变。
