# J460 私有回调框架候选

独立命令行入口为 `--callback-suite`，ABI `ia-lua533-callback-framework-1`。使用原 J460 main.lua 的 41–163 行管理回调，而不是增加 EID 专用字符串分支。框架片段和旧模组源码原样加载；当前只是 Windows x86 金币模型，真实菜单、画面、用途投影和联机门槛仍未通过。

## 实现与约束

每个私有 Lua 环境执行自己的冻结框架片段，拥有独立的 Callbacks 表。优先级排序、相同优先级顺序、参数匹配、false/nil、动态增删、GetCallbacks 的引用、嵌套运行及 Lua 卸载逻辑都由原 Lua 代码执行。数值事件和字符串事件保持不同身份；字符串中的 NUL 和非 UTF-8 字节保留。

原生适配器转发调用并检查配额，不重新实现 Lua 调度。数值内建回调的启用状态只在研究环境建模；没有调用游戏引擎。框架通过局部表取得唯一需要的 debug.getinfo，不向模组公开 debug 库。原有受控 package 表保留，debug 不在其 loaded 表中。

新增 protected_call 保存并恢复原有计数钩子和执行上下文。嵌套转发结束后，外层循环继续受原预算约束。框架最多 256 个事件、256 条记录、4096 字节事件名和 32 层原生转发。回调表可由原接口直接访问，适配器在转发和动作提交边界重新检查容量；这仍是有界扫描，尚未使用字段版本增量省略扫描。

原生桥增加 C 调用帧，类型错误的调用名和堆栈不保证与游戏内逐字一致。未修改 Lua 对照验证的是同一受控后端上的普通行为，不构成当前 J460 原生引擎等价证明。接口文档见 [Isaac API](https://wofsauge.github.io/IsaacDocs/rep/Isaac.html#runcallback)，本轮调度语义以本机冻结框架源码为准。

## 测试范围

当前清单 44 项，其中 30 项功能/恢复检查、14 项预期拒绝检查。完整执行两次；每项包含原版 Lua 和两次研究 Lua。旧图片清单 45 项、SDK 的既有 V3 清单 35 项原样回归。所有结果按各自功能或拒绝预期解释，拒绝不是兼容通过。

检查覆盖字符串注册、数字与字符串分离、二进制事件名、优先级、小数优先级、false 终止与 nil 继续、参数过滤和自定义匹配器、nil 参数数量、self 身份、缓存 API、嵌套参数与结果、重复函数移除、跨模组共享函数移除、运行中增删、列表身份、内建启用状态和 Lua 卸载逻辑。Lua 卸载检查仅证明框架删除其回调，不表示已实现整个长期会话的模组资源卸载。

个人输入、位置、私有变量及 JSON 保存独立；金币只有主机在 authority 阶段提交。失败时通过原检查点和已接受历史重建，核对回调表、配置、私有变量、世界和绘制恢复。这些是明确划分回调的模型案例，**没有证明任意混合回调的通用投影**。

“嵌套调用后无限循环”检查按 1000 万工作单位上限拒绝，没有等到 5 秒超时；32 层转发、别名写表超容量、错误类型、未知归属和消费者捕获也有拒绝验证。初始化和历史恢复成本继续计入账本，未开启全量追踪。

最终两批分别约 19.13 秒和 18.23 秒，包含每项三次独立进程及审计。正常完成与恢复案例的原生运行最高约 0.080 秒、最高 377,715 工作单位、私有提交最高约 5.57 MiB。含进程启动的外部监督最高约 0.743 秒；第二批最高约 0.201 秒。故意耗尽工作量的拒绝案例单独按其预算失败判定，不混入正常运行的最高工作量。正式限制仍为 1000 万工作单位、5 秒子进程和 1 GiB。

## 保留的失败与能力缺口

首轮新清单的两处预期写错：误以为受控 package 不存在，以及误写世界写入守卫的诊断文本。旧 V1 清单和失败记录保留，V2 修正这些预期并增加原框架的类型错误检查。最后审查新增 V3 的回调内 RegisterMod 归属拒绝；对应旧二进制与源码压缩保留，不覆盖历史。

SDK 回归首次误选早期 V1 清单，又套用了需要精灵状态的报告适配器。原始失败输出和适配器快照保留；修正后使用前一候选已验收的 V3 SDK 清单与原 SDK 检查器，未修改旧源码或期望。

新框架尚未接入精确消费者读取集。capture_* 明确拒绝，consumer_read_sets_implemented 对新模式为 false，缓存重用和绘制发布保持关闭。旧整数模式保留自己的读取检查。不能把新框架的初始化通过当成依赖隔离通过。

新框架在初始化之后的回调中动态 RegisterMod，尚未证明应归属哪个模组目录。该入口在缺少明确 sdk_root 时拒绝，防止默认落到入口目录；初始化时的注册不受这条守卫影响。需要兼容的模组若触发此限制，仍属于功能失败，后续应结合真实调用身份解决归属。
