# 实际 MCM 设置结果与分字段保存：部分通过

当前候选是独立 Windows x86 命令行运行时 `ia-lua533-settings-value-1`。
没有游戏附加入口，没有启动游戏，也没有读取或修改个人存档。
主机世界仍是金币模型；当前候选不是可以安装的联机补丁。

保留旧模组源码不变、个人配置独立、奖励跟随主机及
`personal-settings-authority-hud-v1`。这里执行的是冻结 MCM 原文件和明确登记的
API 后端，不把模型绘制命令当成游戏像素或原生 API 等价证据。

## 已接通的路径

普通个人上下文和游戏呈现上下文通过实际 MCM 注册表、设置表生命周期、回调
原型、来源、实际框架消费位置与参数配对。回调体在两个上下文中均执行。
普通个人结果仅在仍然存活的实际菜单消费范围内选择；菜单外的相同缓存函数
仍按 HUD 规则处理。主机奖励通过已有时间线唯一引用，不再次执行世界写入。

目前转发标量结果，保留 nil、false、原始字符串字节及实际返回数量。实际 Vector
可作为登记参数。任意 table/userdata 返回、嵌套设置回调、设置回调中 upvalue
写入和未知副作用尚未通用支持；不能将这些缺口算作兼容通过。

实际 Lua 标准纯函数使用初始化时保留的 C 函数身份，记录每个实际返回槽。
支持登记的 string、math 和 tonumber 子集，未修改 Lua 对照检查了返回数量、
nil、字符串字节及错误。没有按函数名称查找任意模组函数并编造结果。

固定 J460 分发循环只有在实际回调列表、当前行、当前子函数、过滤器、
优先级和列表边界均核对后才取得迭代证明。普通模组循环仍拒绝。

## 保存为何能够保留两套值

旧的整段字节比较会拒绝个人 `private=20`、游戏视图 `private=10` 的正常整表保存。
现在在真实 `json.encode` 后端记录配置来源、编码调用身份、每个字段的实际值、
字段存储/写入/值版本及编码字节哈希。记录不写入模组 JSON。

设置回调进入时保留已登记配置字段的版本。两套序列化结果不同的字段，只有
来源对应且本回调没有改变其字段版本时，才能按已接受上下文的原值透传。
其他表写入仍逐条核对。保存前的私有字节若已分开，须对应此前接受的配对保存
回执。普通个人字节发布到研究存储；呈现字节留在私有研究上下文。

字符串改写不能沿用编码回执；A→B→A 也不能取得“未修改”证明。保存后错误会
丢弃候选并重建已接受历史；重复帧返回缓存。这里的回执仅覆盖当前上下文和
历史重建，尚未实现从 LoadData/Decode 重载两套状态的持久侧车。

## 边界修复与历史失败

精简子表来源追踪后，旧边界测试暴露出未登记表长度变成无来源数字的问题。
修复为：在活动时间线内给这类引用长度保留显式依赖，不遍历对象内容。
它参与游戏投影时拒绝；不据此把未知操作当成纯界面。

第一版更广的操作数校验误拒绝已有个人字符串和分支案例，已移除。失败报告
`settings-value-branch-regressions-v2`、`settings-value-original-gates-v2`
与先前错误接受的 `settings-value-controls-v3` 保留。`functional-v6`
测试驱动没有区分新保存证明和返回证明，报告收集失败，不能算验收结果。
`branch-regressions-v3` 在构建未结束时启动，遇到文件占用，整批作废。

最终使用同一对二进制串行执行，逐例重复运行；具体二进制、源码和结果哈希见
`reports/settings-value-progress.json`，校验入口为
`tools/verify_settings_value.py`。

| 清单 | 结果及意义 |
|---|---|
| 原实际 MCM 值清单，7 项 | 全部通过，包含两套设置交换、私有分支、原保存反例、去重和重建 |

| 边界 2 项 | 普通循环无权使用 SDK 迭代证明；未知表长度不能混入奖励投影 |
| 标准原生标量 2 项 | 未修改 Lua 对照，以及 format/find 在主客不同数值时的 HUD 结果 |

保存清单整体失败不能改成通过。预期拒绝与功能兼容分开统计。

正式保护线保持 1000 万工作单位、每子进程 5 秒、1 GiB Job；来源图仍为
4096 节点/1 MiB，没有扩容。审计导出可以只保留图摘要，执行图仍驻内存，
没有读取历史审计文件参与执行。摘要不等于导出了完整依赖图。
工作单位是明确的混合记账，不能换算为原生指令数或实时帧性能；报告的内存
是结束时私有提交量，不是完整的峰值曲线。

## 下一步与阶段判定

本候选的完整门槛仍为失败。连续菜单操作的容量失败要求先补齐活跃图引用根、
字段/upvalue/闭包/原生对象的保留关系，再在提交边界回收不再被使用的记录。
不能清空图、丢失跨帧来源、默认过期引用有效或放大容量来通过。

之后继续双视图配置重载侧车、真实 EID 空图片替换与字体控制字符契约、
完整菜单/HUD、集中游戏画面核对。原生模拟接管、通信、断线暂停与恢复、
各自解锁和双机连续 30 分钟验收仍未完成。

`settings-value-progress.json` 是当前可变研究候选的检查点；测试清单和逐例
报告保留原字节，既有 sealed 祖先不改动。没有新建 ZIP、解压副本或复制游戏
图片字体。目标保持 active，不能报告任意旧模组兼容或可玩联机通过。
