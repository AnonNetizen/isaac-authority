# 固定容量审计批量写入

约束：独立 Windows x86；10000000 工作上限、每个命令行子进程 5 秒；不改冻结模组源码、个人配置及主机奖励规则，不启动游戏、不写个人存档。保留 init-profile 的代码、二进制、清单和失败报告，仅增加一个派生候选和一个构建目录，不复制模组或生成 ZIP。

实施顺序：

1. 使用固定 256 KiB 缓冲。完整小记录复制入队，空间不足时同步提交已有完整记录；超过容量的记录先排空缓冲，再沿用最多 64 KiB 的直接写入，不创建额外大缓冲。原 8 MiB 单条、16 MiB 测试文件限额及全局分配限额不变。
2. 区分逻辑 end/sequence、已完整提交文件的 end/sequence，以及 FlushFileBuffers 成功的 durable end/sequence。文件前缀只在整批写入成功后前移，失败时保守保留旧位置；强制杀进程时可丢失未提交缓冲，不能宣称完整会话。
3. 保留 CRC、顺序、偏移和相同审计字节。仅登记过的诊断读取可以先排空缓冲；执行期历史读取仍禁止。阶段/帧边界显式 flush，成功退出须 close_checked；析构属于异常放弃，不偷偷吞掉失败再宣称提交。
4. 复制、真实 IO、校验和提交检查均计费。拒绝、超预算、部分写入和刷新失败锁存，后续 append/read/flush/close 不能继续。失败上下文废弃，在新上下文重放已接受历史恢复；不尝试向故障文件追加。
5. 同一个 Journal 实现做独立短测：空/满/跨边界、大记录、诊断读取后再写、计费拒绝、文件配额、短写、部分写后失败、FlushFileBuffers 失败、正常关闭和强制终止。事务夹具暂存金币、个人配置、私有变量、RNG、保存和绘制，只有审计刷新成功才发布；故障后重建已提交历史，与无故障结果核对。它仅证明金币模型事务，不代替游戏恢复。
6. 冻结 37 项模型清单原样回归，核对原型前后的完整证明及逐字节审计、独立解码、重复帧/个人值与权威值；小基准比较 WriteFile/seek 次数、工作量、内存与墙钟。全部通过后才各做一次 MCM、EID、组合的 5 秒初始化。

新增私有 ABI `ia-lua533-audit-batch-1`，保留即时写入诊断开关作同二进制对照。共享采样区沿用已有 32 KiB 机制。任何初始化仍超时或被配额拒绝均保留失败结果，不扩大限制。测试结束删除已校验的原始审计及明确命名的 C++ 中间文件，仅保留紧凑结果和唯一失败证据。
