# 字段与 upvalue 写屏障验收

本轮写屏障门槛通过：32 项功能、6 项安全拒绝、18 项原边界入口回归。每项新案例的候选程序执行两次，版本、对象生命周期、普通结果均一致。支持范围内与独立的原版 Lua 5.3.3 程序对照；新能力的容量拒绝、原生重绑定拒绝分别列出，没有算作兼容成功。

## 实现

独立 Windows x86 入口 `build-write-barrier/Release/authority-writes.exe --write-suite`，ABI 为 `ia-lua533-boundary-writes-1`。`authority-writes-reference.exe` 链接之前保留的原版 Lua 静态库，不链接改过的解释器。二者使用同一金币模型后端。官方源码、旧候选和冻结模组均保持原哈希。

`write_barrier_runtime/prepare.py` 校验官方源码和替换锚点，生成独立构建源；没有改动 TValue、Table、UpVal 或 Lua 全局状态布局。C 屏障只传递瞬时键及目标地址，C++ 侧只保存当前计数和选定字段，不调用 Lua、不构建逐值图、不回读审计文件。异常锁存为整个上下文失败，禁止提交半帧。

- **字段：** 实际表身份、带类型的键与字段版本。覆盖普通/缓存 rawset、C API rawset/rawseti/rawsetp/setfield/seti，以及 table.insert/remove/move/sort。Lua 的整数 1 与字符串 `"1"` 分开，数值 1.0 按 Lua 规则对应整数 1。同值赋值也递增；新增和删除另改结构版本。
- **目标与搬运：** `__newindex` 转发只记录真正被写的表；失败写入不记。扩容和重哈希不额外递增字段版本。表元方法绑定另有版本，尚不能凭原始字段版本证明一次含元方法查询的完整依赖。
- **upvalue：** 实际捕获单元身份及当前槽地址。值存储宏的固定桶索引覆盖尚未关闭的局部变量写入、关闭后的 SETUPVAL 和 C API setupvalue。栈扩缩与闭包关闭只搬迁索引；共享闭包使用同一单元。
- **生命周期：** 回调最后一个登记所有者移除时注销监听；表释放时立即退休字段元数据。弱表清理在清除前记录，监听本身不保活表或对象键。重新分配获得新生命周期编号，不把地址重用视为原对象。

版本从登记监听时开始计算。对表字段只按显式请求登记；对 upvalue 只登记真实回调直接捕获的单元。没有追溯先前写入，没有自动递归遍历闭包或整张配置表。

## 关键结果

| 检查 | 结果 |
|---|---|
| 字段 A→B→A、缓存 rawset | 版本增加 2，最终值仍为 A |
| 开放捕获单元初始化时两组 A→B→A | 关闭前 4 次写入全部保留 |
| 两个共享闭包各写一次 | 同一单元增加 2；移除一个所有者不换身份 |
| 栈搬迁、闭包关闭、普通 GC | 只记录位置搬迁，不多计赋值 |
| 兄弟字段 3,000 次写入并触发表扩容 | 选定无关字段版本不变；没有扩容搬运的虚假写入 |
| 同一字段写 20,000 次 | 仍只保留 9 个选定字段，历史写记录为 0 |
| 弱表哈希和数组值清除 | 各一次字段及结构变化；再次 GC 不重复计数 |
| 弱对象键清除 | 对象正常回收，结构变更，其他字段不失效 |
| 移除、GC、重注册 30 轮 | 30 个旧表和旧单元退休；活跃字段 1、活跃单元 5 |
| 保存和绘制后失败，包括 pcall 吞错误 | 私有状态、版本、配置、世界和 RNG 经重建恢复 |

最终短测批次约 8.08 秒，包含全部子进程启动、重复运行和旧回归；不是单案例超时。最长子进程约 0.126 秒。新功能案例中耗时最高的一项为 20,000 次写入：原生计时约 5.54 毫秒、80,515 工作单位。这是小模型数据，不能推断真实 MCM/EID 的性能。

## 预算、拒绝及未完成部分

- 1000 万工作上限、每个子进程 5 秒、1 GiB 进程上限不变。写入、键处理和生命周期事件纳入账本；Lua 指令继续每 64 条保守预付。单位与旧全量追踪不同。原版 C 标准库的所有内部计算尚未单独计费，由外部超时和进程配额补充约束。
- 每上下文最多 1024 个捕获单元和 1024 个选定字段。没有逐写历史；回调及恢复所需的已接受命令历史仍由旧会话层保留，不能据此声称一个长时间运行的联机会话已具有固定总内存。
- 本阶段仅支持选定字符串和整数键。其他键的写入能改变表结构计数，但不能登记为精确字段消费。未知选键、原生 upvalue 重绑定、容量超限均明确拒绝。第三方直接写内部指针不在已登记 API 中，也没有开放原生模块加载。
- 消费者读取集合、元方法读取链、跨函数依赖摘要、最小表达式、主机贡献投影尚未实现。旧的观察诊断接口保留；只有新 `inspect_writes` 的版本代表登记后精确写次数。
- 个人配置继续独立；世界写入和随机数仍只允许主机权威阶段。个人绘制队列仍不可发布。保留 `personal-settings-authority-hud-v1` 要求，不能把本轮写屏障通过等同于奖励显示隔离通过。
- 没有启动游戏、加载真实 MCM/EID、修改个人存档、重新启用全量追踪或创建研究 ZIP。

## 复现入口

先运行 `python -B authority/tools/verify_boundary_writes.py` 核验交付和保留文件。

运行冻结短测：`python -B authority/tools/run_boundary_writes.py run --output <新的空结果目录>`。固定清单为 `research/boundary_writes_v2.json`；每个子进程由脚本强制 5 秒超时，整批最多 60 秒后停止启动新案例。旧 18 项原清单按原预期回归，其中观察版本无法看见 A→B→A 的历史结论仍保留。

重建时先运行 `python -B authority/write_barrier_runtime/prepare.py`，再用本机 Visual Studio CMake 配置 `write_barrier_runtime` 到唯一的 `build-write-barrier` 目录，生成器 `Visual Studio 18 2026`、架构 `Win32`、配置 `Release`。保留静态库、EXE、生成源和哈希；只清理本次构建可再生中间文件。较早的两份短测结果经完整字节校验后无损压缩，不保留重复明文或资源副本。

下一道门槛是按消费者登记实际读取的字段和捕获单元，并证明兄弟字段写入不失效、真实读取项的 A→B→A 必须失效。先完成该门槛的有界模型短测，再考虑真实 MCM/EID 初始化。
