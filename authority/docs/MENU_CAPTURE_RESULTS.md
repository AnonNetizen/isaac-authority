# 真实 MCM 命令捕获与向量交接：2026-10-17

独立 Windows x86 CLI `ia-lua533-menu-capture-1` 已能用脚本化个人按键打开未经本轮修改的冻结 MCM，捕获两帧真实菜单调用。启用第三呈现上下文后同样通过，主机实际执行自己的关闭菜单回调并保持关闭；模型世界和存档未被菜单修改。尚未进行原生画面重放。

EID 与组合 HUD 尚未通过。可信设置用途和配置重载侧车也尚未实现，本轮不能宣称菜单中的个人设置与奖励混合 HUD 已完成隔离，更不能用于实际联机。

## 本轮代码

`Sprite.Render` 捕获完整的原生 API 程序，而非依靠最终 `GetFrame()` 重建画面。每个受控精灵保留 Construct、Load、Play、SetFrame、ReplaceSpritesheet、LoadGraphics、Update、Color、Scale 的有序版本；每次绘制保存当时的程序、资源与图片哈希、位置和裁剪参数。缓存 Render 方法、同帧两次属性变化、图片替换和重建均覆盖。未知操作仍拒绝。

绘制前验证冻结资源及已加载图片，使用原有固定容量绘制队列。精灵程序最多 128 操作、共 1 MiB；GC 退役时释放对应程序及元数据。查询无法确认的默认状态不会编造成具体值，而由已记录的构造和 API 程序留待原生重放。

已登记的 void `Sprite.Update` 在命令捕获后端可以保留为待重放操作。超出已核对的动画状态模型时，帧号及播放标志查询明确拒绝，捕获结果不填入假帧号。测试要求该类绘制的 `model_state_queryable=false`、帧号为 null，并验证随后 GetFrame 被拒绝。没有执行原生 Update 或验证像素。

真实 MCM 的 ScreenHelper 还暴露了两个来源缺口：通用 Lua 算术标签覆盖了原生向量结果；WorldToScreenPosition 的计算结果没有连接变换矩阵和输入。现通过一个私有 VM 结果交接点保留受控向量的实际生产者，并将屏幕变换连接到明确权威状态时点的矩阵与输入。

初始化只为活跃向量记录构造参数及字段版本，不给全部 Lua 值建图；到实际消费时才生成需要的来源节点。构造记录最多 256 KiB，随 userdata 退役回收。向量加、减、除和取负按实际 binary32 运算传播，表别名保留字段版本。已变更或没有登记来源的对象仍拒绝，没有通过数值相同选择来源，也没有关闭来源校验。

显式 `end` 帧的只读查询直接读取已绑定的不可变快照，无需再证明读取位于主机相同指令位置；其世界写入仍只记录个人意图。捕获、重放时点及随机、金币贡献的严格匹配继续保留。这不是给循环中的世界贡献放行。

## 真实契约和结果

`research/menu_capture/mcm-contract-v1.json` 固定实际 MCM 源码 SHA256、AddSetting 调用形式以及 CurrentSetting、OnChange、Display、翻译和 Info 消费位置。位置只作诊断，不当作信任证明。

四项原版 Lua 对照实际执行原 MCM API：AddSetting 两参数、nil 子分类、返回原设置表和原函数身份；回调参数、false/nil/返回个数；原错误行为。没有包装或改写模组源码和设置回调。设置用途的实际函数身份与返回值传播尚待实现，这些 API 探针不等于用途边界通过。

最终有限模型共 16 项运行两次：11 项功能或恢复通过，5 项拒绝诊断正确。另有上述 4 项真实 API 契约、原 35 项 API、20 项分支隔离及两个原始状态/HUD 门槛回归通过。

两项真实 MCM 捕获均通过：由个人 L 按键打开，随后个人释放按键；主机执行自己的未按键回调仍关闭。两帧各捕获 6 条精灵和 14 条字体命令，包含源码对应的「通用」「Mod配置菜单」「同步游戏设置: 是」「ESCAPE」「ENTER」。精灵、字体、字节、坐标、设置及程序版本重复运行一致，实际场景仍包含原来的两个玩家和道具，没有返回空实体列表绕开回调。

三上下文用例本次约 0.335 秒、567,028 工作单位、16,953,344 字节私有内存。个人和呈现上下文各按需物化 14 个初始化向量来源，保留的构造描述各约 12 KiB。没有启用初始化全量追踪或回读历史审计。

## 阶段边界与下一步

捕获是命令行研究后端的调用和资源证据，不等于原生重放、布局/像素等价或任意旧模组兼容。这里的 MCM 权威锚点没有奖励贡献；同一字段在真实菜单显示个人值、普通 HUD 显示主机值的混合用途仍需单独验证。

下一步接入真实设置对象、框架函数原型及消费指令的可信身份，贯穿回调返回和绘制消费，再实现配置重载侧车。EID 的空图片操作与控制字符度量另需明确契约，不能靠放宽通用资源校验解决。菜单导航、个人配置差异与保存重载、原生画面、长会话回收仍未验收。

原生 J460 模拟接管、完整实体和房间同步、Steam 通信、断线恢复、独立解锁及双机连续 30 分钟验收仍未完成。用户目标保持进行中。

所有运行保持 1000 万工作单位、5 秒、1 GiB 保护线。没有启动游戏、修改个人存档、复制游戏资源或生成新的 ZIP/解压目录。复现入口：
