# 独立呈现上下文与分支选择：2026-10-17

Windows x86 命令行 ABI `ia-lua533-branch-views-1` 已在唯一权威引用可解析的模型案例中，解决普通值和游戏视图选择不同 HUD 分支的问题。旧模组源码未改动。当前仍不是可安装、可玩的联机补丁。

## 执行与提交

候选保留主机和个人上下文，另为个人建立一个持久的呈现上下文。个人上下文按个人值执行，保留配置、私有变量、输入处理、保存及音效。呈现上下文拥有独立 Lua 状态和模型世界副本，读取同一不可变权威帧；它按游戏视图选择已证明关联世界贡献的条件，保留显示状态，并生成最终候选绘制。其保存和音效不发布。

这允许同一字段和闭包状态同时有两种视图。例如个人 `amount=2`、主机贡献为 1 时，个人分支仍更新 `other`，呈现分支更新 `one`；随后另一个回调继续分别读取两个私有状态。个人语言和按键处理照常执行，界面位置从个人坐标出发。奖励条件控制的位置变化在呈现视图中选择主机条件，个人保存仍按个人执行结果提交。

对含保存的分支，实验同时检查两份私有配置及最终发布内容：普通个人配置变成 202、呈现配置变成 102 的案例，只发布 202，HUD 仍按已唯一关联的主机贡献显示 1。102 留在运行时侧呈现视图，不写入安装目录、个人研究存储或模组 JSON 格式中。可信设置菜单边界尚未实现，因此这不证明菜单可以直接使用呈现上下文的配置。

两份执行都成功后才接收本帧。任一上下文失败，丢弃候选，从初始状态及已接受历史重建全部上下文。覆盖个人保存已经执行、呈现绘制已经入队后才失败的情况；不存在退回普通 HUD 的成功路径。重复帧复用同一组合回执，同编号不同输入的既有拒绝规则不变。

## VM 接口与预算

只派生一个私有 CLI `lvm.c`，在 EQ、LT、LE、TEST、TESTSET 决策处读取已有的字段/upvalue 来源及明确操作数。普通执行和主机执行保留原决定；呈现上下文仅在唯一游戏引用可求值时选择游戏视图。记录原操作数、游戏操作数、原决定、选择和引用操作身份，且核对普通比较与 Lua VM 一致。未证明的操作数不能因为碰巧等于源码常量而接受。

配置身份、世界贡献和显示使用沿用实际来源图，未按模组名、字段名、文字、数值相等或调用顺序匹配。权威绑定索引在每个呈现帧内只建立一次，读取和编码计入工作账本，不读取历史审计文件。

沿用 1000 万工作单位、5 秒子进程超时、1 GiB 私有内存；初始化及历史重建计入账本。新呈现路径每帧最多改变 8 个条件，证明最多 64 条/64 KiB。没有打开未解析路径的无限探索。它是已解析引用的独立执行，不是任意模组的符号执行或完整延迟随机分支求解器。

独立第三上下文在会话初始化时建立，成功帧间保留状态；正常逐帧执行不重新初始化整份模组。世界副本和帧绑定更新后，两份执行都只引用已产生的主机操作，随机生成器不会再次执行或回退。所有新查询和世界 API 仍受父候选契约约束。

## 验收

- `research/branch_views/suite-v2.json` 共 20 项，各执行两次：14 项功能或恢复通过，6 项拒绝诊断正确。包括原冻结的奖励控制 HUD 源码与主客数值交换、个人输入/语言/保存、表别名及辅助函数、跨帧私有状态、条件控制位置、双配置视图、重复消息与历史重建。
- 个人执行成功后，呈现分支在保存、私有状态和绘制后注入失败；直接观察两份闭包和 GetData，确认整帧恢复。多候选、未知操作数、9 个改变条件、Lua pcall 吞错及缺失重载侧车均明确拒绝。这些拒绝不算模组功能兼容通过。
- 两个原始状态查询/HUD 模型门槛在启用新上下文后通过；源码、配置、输入和显示预期保留，只增加帧协议开关。HUD 引用证明来自实际呈现上下文，未要求普通个人状态被投影覆盖。
- 原 26 项随机清单和 35 项 World View API 清单以原模式、原预期回归通过。新的三上下文随机案例另检查个人和呈现各引用一次同一主机结果，主机仍只抽取一次。
- 冻结且未经本轮修改的真实 MCM、EID、组合源码均完成三上下文初始化，普通两份上下文与原版 Lua 控制一致；第三上下文和证据重复一致。三类初始化最大约 1.196 秒、3,606,121 工作单位、87,650,304 字节私有内存。没有执行真实菜单导航或画面重放。

预览报告 `reports/branch-views-preview/result.json.gz` 保留一个诊断步骤错误：多候选已经拒绝后，测试又要求发布同样歧义的 HUD。最终清单将后续这次绘制也明确要求拒绝，并核对两份私有状态恢复；未放宽多候选匹配。首个正式报告驱动在复用随机案例时缺少存储所有者元数据而中断，修正为读取冻结 SDK 存储身份，记录于 `reports/branch-views-v1/failure.json`。这两次修正未修改原反例源码或功能预期。
