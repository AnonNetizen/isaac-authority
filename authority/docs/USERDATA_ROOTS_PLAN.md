# Userdata 根与真实初始化：执行顺序

本阶段保持 10000000 工作单位、x86、旧模组源码与个人设置不变。只运行命令行；不接入绘制、菜单导航或游戏。旧 compact 交付由已校验 ZIP 与哈希保留，复用原构建树。

1. 登记确定的 `uservalue-table-1` 根契约。私有 UI 后端将背后状态表放入 Lua uservalue，移除注册表对对象和状态的永久 pin；补齐 uservalue 的生产者/来源字段。回收器扫描真实 Lua GC 链及 uservalue，原生释放时移除地址索引。未知类、未登记契约、错误形状明确拒绝。
2. 用同一后端分别运行官方未修改 Lua 与研究 Lua。覆盖七类 UI 对象、状态字段、闭包、别名、循环垃圾、字段来源、主机奖励引用、个人值与位置、跨上下文隔离、缓存方法、未知/失效契约。先通过这一门槛，不用真实大模组掩盖根错误。
3. 复用冻结 MCM/EID、SDK 和资源元数据；逐个进程运行中英文 MCM、EID、组合六例，分别对照官方 Lua。初始化、检查、根追踪、编码与 I/O 同一账本累计，不能清零、降费或扩预算。记录首个拒绝位置、累计工作与内存；拒绝是功能失败。
4. 完成当前 51+13 项存储回归和新根案例两次。只保留一套活动构建与唯一审计；相同重复文件验证哈希后移除。通过或失败都写明结论，不以有限模型代替真实菜单、HUD 或任意模组兼容。

限制：本契约仅适用于已登记的研究 UI userdata，不自动涵盖游戏内原生对象的隐藏指针。历史证据仍落盘，必要索引仍有界增长。真实初始化若首先触及预算或其他尚未支持入口，保留失败，不更改原反例或源码。

## 本轮结果（2026-10-15）

userdata 根模型通过；真实 MCM/EID 初始化门槛失败。冻结的中英文 MCM、EID、组合六例分别运行两次，官方 Lua 对照全部完成；研究运行时的十二次执行均触及 10000000 上限而未完成。拒绝发生在不足以支付下一笔收费时，因此已用工作量可能略低于上限；没有追加预算。

这些是停止时采样，不是整个过程的峰值或游戏帧成本。该批未出现分配失败；这不证明所有模组长期运行内存恒定，也没有测出完成初始化的总工作量。

根清单 `ui_userdata_roots_v7.json` 共 9 例：6 项功能、3 项安全拒绝，各执行两次。七类对象、别名与缓存方法、字段来源、循环回收、userdata 表键、主客数值交换、对象销毁后的显式宿主 pin 与未声明引用均符合预期。24 批循环中回收 384 个临时 UI 对象，每批剩余登记对象为 1；保留奖励值的宿主 pin 不会把已经死亡的 userdata 本身固定住。未声明的历史奖励引用继续拒绝，不能降格成个人值。

原 51+13 项存储回归在同一最终 DLL 上各重复运行两次通过，仍分开记录功能与安全拒绝。旧 13/31/24/42/56 整套模式未在本轮重跑；真实世界、菜单、HUD 和通信未接入。真实六例未走到初始化后的根回收检查，因此不宣称真实 MCM/EID 完整回收通过。

## 已落实的实现

- 私有对象后端与官方 Lua 对照均改用 uservalue 表；移除对象和背后表的注册表永久 pin。来源、生产者和存储版本经过 uservalue 读写保留，VM 释放 userdata 时清理地址索引。对象总构造限额 2048 保留，尚不能据此支持无限长的 UI 会话。
- 原生构造契约区分对象身份与背后字段内容，避免把所有配置字段都传播为“对象是否存在”的来源。具体字段依赖仍被记录，未知调用不当作纯操作。
- 登记 userdata 的表键采用稳定逻辑编号；Lua 官方实现的 HOOKKEY、CLIBS 和主线程采用固定角色名。只识别已核对的实际槽与对象，未知指针仍拒绝，不把内存地址写成跨运行身份。模组直接修改追踪钩子仍拒绝；SDK 的钩子安装通过未修改真实源码入口验证。
- 真实入口复用确定性 API 后端，读取冻结源码、SDK 和资源索引；健康检查不再构造整份历史图，完整事件按既有审计格式落盘。没有省略真实源码、替换不支持接口为空操作或跳过收费。

## 重复性与剩余瓶颈

真实六例的两次证据不一致，这一门槛也未通过。流式逐记录对比定位：MCM en、EID en 与组合 en 的前 56905 条记录相同，第 56906 条首次不同，是冻结 `enums.lua` 的 `AddEnumToNamespace` 中 `pairs`/`next` 返回不同枚举键（源码第 5011 行）。差异记录保存在 `real-six-v2/first-evidence-differences.json`。尚未为“对齐证据”改写枚举或模组的遍历顺序。

最后耗尽预算的位置会随执行顺序变化，不能把最后一个收费项视为主要成本。MCM en 第一次的审计校验、审计读取、冷证据读取合计 4760151 工作单位。下一轮应先定义并验证研究上下文的可重复执行输入，再优化已证明重复的读取/校验及存活性分析；继续按原收费和上限验收，不给真实源码单独放宽。

失败日志是初始化前缀，不是可提交的完整帧。落盘记录另由流式 CRC/序号检查核验；预算用尽后的 finalize 没有成功，不能把前缀 CRC 正确写成整个帧完成。

## 历史记录与测试入口校正

预检失败保留原位：最初跨帧对象身份被字段来源污染；之后真实加载先拒绝未支持的原生注册表键；修复后才暴露当前预算门槛。新测试还有三处入口/预期错误，分别保留 v2、v4、v6 清单与失败结果：没有登记 `__eq` 的直接构造对象应使用 `rawequal` 检查身份；模组直接调用 `debug.sethook` 应属于安全拒绝；复用的 `empty.lua` 实际明确返回 0。修正均未修改旧模组或这些冻结 Lua 文件，未更改实际功能要求与奖励引用预期。
