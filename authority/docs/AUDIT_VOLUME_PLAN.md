# 审计拒绝分类与体积优化

继续独立 Windows x86 命令行研究，10000000 工作上限、每子进程最多 5 秒；保留 8 MiB 单条解码限制、16 MiB 测试文件限制、256 KiB 写缓冲和既有内存限制。不启动游戏，不改冻结模组、个人配置或存档。个人设置独立、奖励及其 HUD 跟随主机的规则不变。

按以下顺序推进，不用扩大限制替代通过：

1. 增加固定大小拒绝快照：确切原因、通道/编号、载荷与头部大小、记录上限、文件已用/剩余空间、pending/submitted/durable 位置，以及两种条件是否同时超限。逐通道累计记录数、载荷、最大单条和头部开销。诊断不读取历史文件；记录首个失败后锁存。
2. 短测区分单条超限、文件耗尽、同时超限，复用原 20 个完整性/恢复夹具及 37 项模型清单。通过后，MCM/EID/组合各做一次 5 秒诊断，按实际占用决定首个体积优化目标。
3. 只对已证明的无损表示做优化，不丢弃依赖、世界操作或审计记录，不把哈希相同当作证据相同。编码/解码、索引和比较成本都计费，新增工作区固定容量；保留未优化诊断模式。
4. 如果采用压缩格式，16 MiB 指实际文件字节，8 MiB 仍限制每条解码载荷；必须另外限制压缩工作区、解码长度与工作量，明确报告原始/存储字节。不能扩大原始记录限制，也不能悄悄修改已冻结清单。只允许诊断读取解码，执行期仍禁止历史回读。
5. 同一冻结输入比较完整解码记录、语义证明、编号/顺序/CRC、恢复与去重；注入损坏、截断、短写、刷新失败、超预算和强制结束。短基准通过后才再测三项初始化。需要兼容的案例拒绝仍判功能失败。

保留旧候选与失败报告，仅新增一个派生源码目录和一个构建目录。原始审计校验后删除，不新增 ZIP、模组副本或重复解压。交付精确拒绝结论、体积账本、完整性与恢复报告及明确阶段结果；不能完成时不宣称已支持真实菜单或联机。
