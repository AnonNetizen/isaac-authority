# Vector、Color、KColor 的有限模型结果

本候选增加值对象的身份、字段版本和弱引用回收，冻结模组源码保持原样。正式入口为 `--value-suite`，私有 ABI 为 `ia-lua533-value-objects-1`。保持 1000 万工作单位、每个子进程 5 秒、1 GiB 私有提交配额。没有启动游戏或修改个人存档。

40 项模型分类检查及 270 项旧模式分类回归达到各自原预期。**真实 MCM/EID 初始化仍未通过，完整用途投影和联机目标未通过。** 40 项包含 25 项功能/状态/恢复检查和 15 项明确拒绝检查；拒绝不是功能兼容。每项使用未修改 Lua 的对照结果和两次研究运行结果，均保留在压缩报告中。

## 接入范围

原样执行冻结 J460 `resources/scripts/main.lua` 的 171–189 行常量段及 232–248 行 Color/Vector 包装段；按完整文件及片段哈希核验，不重写模组。使用 `Vector.X/Y`、`Color.R/G/B/A/RO/GO/BO`、`KColor.Red/Green/Blue/Alpha` 的登记字段。支持基本向量运算及 Length、LengthSquared、Dot、DistanceSquared；未核实的 Rotated、Colorize、不同对象相等和字符串格式明确拒绝。

对象分量采用有限 IEEE binary32 模型，6 组独立 Python 打包字节样本包含舍入边界、负零、次正规数及大数。原版 Lua 和研究 Lua 共用同一个模型后端，因此一致结果只说明追踪未改变此模型的执行；**尚未证明游戏原生数值、着色、渲染或 ABI 等价**。

每个上下文有独立对象编号、代次及字段版本。读取只登记被读取分量；同字段 A→B→A 使消费者失效，无关分量不使其失效。缓存方法与字段访问器重新检查实际接收者。个人位置、颜色、保存和主机金币结果的有限案例保持独立，失败后的对象、配置及绘制队列通过历史重建恢复。

Lua 弱值索引不永久固定每个对象。类常量正常保留 12 个对象，主夹具另保留 3 个。构造时轮转检查最多 8 项；检查点及受保护调用结束执行完整活跃集合清理，正式活跃记录上限 1024。此实现仍有有界全扫，不能说所有回收路径均为常数成本。8192 个短命对象和覆盖 `__gc` 的 2048 个对象回收至夹具基线。另一个混合短测交替创建 Vector、Sprite、BitSet128，防止旧 Vector 地址记录误撤销新对象的登记；有限运行不证明覆盖每种分配器地址复用顺序。

第一批 39 项通过后，封存前发现跨类型地址复用的登记边界，保留首次二进制和源码压缩快照后修复，新增第 40 项混合检查。未改旧框架源码；两份原 include 派生为独立文件。旧失败报告与编译诊断均保留。
