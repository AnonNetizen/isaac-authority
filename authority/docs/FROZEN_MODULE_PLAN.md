# 新架构的冻结模块入口

继紧凑观察优化后，真实入口测量停在 MCM 的 `scripts.filepathhelper` 与 EID 的 `Game()`。本阶段先补通用模块加载，保留旧源码、旧结果及正式配额，不伪造游戏接口。

1. 独立 `ia-lua533-frozen-modules-1`；从固定哈希清单一次加载只读源码目录，主客共享不可变源码字节，各自拥有 Lua 状态、缓存、私有配置及闭包。引用官方 Lua 5.3.3 的原始 require，实现仅指向冻结文件的搜索器，删除本机文件/DLL 搜索器。
2. 按实际 Lua 调用者的冻结源码根定位嵌套导入。普通找不到模块、语法和执行错误仍按 Lua 规则可捕获；路径/哈希/未登记原生能力错误锁存整帧失败。缓存命中不重新读文件或历史审计。支持受控 dofile/include，不开放任意文件、DLL 或二进制代码加载。
3. 和独立原版 Lua 对照缓存身份、false/nil、预置 loaded、preload、模块参数、重复加载、异常重试、跨模块闭包和主客配置。验证恢复后不会保留失败加载的缓存/私有状态，未知世界写入仍被拒绝。
4. 全部通过命令行 1000 万/5 秒短测后，尝试冻结 MCM、EID 和组合入口，记录编译到的文件与下一个真实失败。加载器通过不等于真实初始化、菜单契约、绘制或奖励投影通过。

源码与模块编译计入账本，保持 1 GiB 子进程上限及现有字段/消费者/快照配额。源码最多 4096 文件、32 MiB、单文件 4 MiB。只建一个新运行时目录，不复制模组或资源，不启动游戏、不修改个人存档，也不重新开启全量追踪。
