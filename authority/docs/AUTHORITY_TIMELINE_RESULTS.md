# 权威状态时间线和 HUD 引用：2026-10-17

独立 Windows x86 命令行 ABI `ia-lua533-authority-timeline-1` 已让两个原始失败模型在显式主客帧绑定下达到原预期。仍未实现可玩的联机扩展，通用旧模组兼容门槛没有通过。

## 已实现的行为

主机帧在开始和每个已登记世界操作之后保存独立模型快照，包括菜单场景、游戏场景和金币。当前提交操作是玩家零金币、玩家位置/速度/控制开关及已验证的 seed effect 10。帧完整成功后才发布快照和操作记录，失败不发布本帧。

个人帧通过会话协议明确指定主机帧。`replay` 从该帧开始状态逐步引用操作；`end` 明确指定该帧结束状态，供独立界面查询。缺失、过期或没有绑定的帧均拒绝，不能退回当前世界或最近一帧。这是测试协议中的帧关系，没有给模组源码添加标记。

重放操作同时核对已登记 API 和目标、固定源码/函数字节码与完整有限调用上下文、操作数依赖、控制记录以及状态边界；只存在一个候选且边界衔接才引用。它不靠参数数值相等或调用次序选择操作。循环需要迭代证明，当前直接拒绝含回边的相关函数。无来源的参数必须能证明来自字面量；数值碰巧等于字面量的闭包输入会拒绝。带来源的表达式也不能替其中未证明的操作数背书。

个人世界写入不提交，原生 void 操作保留零个返回值。重放结束时必须引用全部对应操作。已执行过的查询须匹配唯一主机状态锚点；显式结束帧可新增只读查询。玩家二的金币独立读取，不借用玩家零；房间、实体、玩家与游戏场景查询读取绑定快照。尚未覆盖的原生游戏接口不因此获得等价性声明。

已唯一关联金币贡献的普通 HUD 标量，按 `personal-settings-authority-hud-v1` 在消费处求值；语言、位置和未关联配置仍用个人值。配置字段的游戏视图身份来自实际 SDK 存储所有者、槽和 JSON 路径，并关联实际权威消费；世界操作匹配仍保留生产者和版本证据。纯表达式使用 Lua 运算，先检查不投影时是否复现原执行值，再选择主机引用；不根据界面文字或字段名称猜奖励。

投影只修改本次原生绘制调用的实参，不回写配置和 Lua 私有变量。相同权威值可用于多处显示，无需再次执行或消费世界操作。`replay` 中个人额外出现的 HUD 也应用该规则。该模式固定规则，不能通过协议关闭主机 HUD 视图。可信设置菜单用途、Font/Sprite 的完整投影及真实画面仍未接入。

## 原失败案例的结果

复用 `world_view_required_mixed_v1.json` 和 `world_view_required_projection_v3.json` 的原 Lua 源码、配置、步骤和结果预期；只为新模式添加帧关系。旧版本及其失败记录保留。

- 相同混合回调现在显示 `false:160.0>true:17.0`，查询分别来自修改前后状态。四次修改引用主机记录，个人不再提交金币、位置、控制开关或 seed effect。
- 普通 HUD 显示 `zh|setting=1|coins=1|worldx=17.0|hud=true|private=1`；个人保存仍是 `amount=2, language=zh, x=147`，界面位置 147。交换主客值后显示随主机反向变化，未固定成 1。

这证明显式模型协议下的两个原门槛，不代表无需帧协议的旧观察器已经改变，也不代表实际游戏里的同类回调全部兼容。

## 验收与资源

最终冻结清单 `research/authority_timeline/suite-v8.json` 共 30 项：18 项功能与恢复验收通过，12 项只证明拒绝诊断正确。每项执行两次私有运行时；原版 Lua 执行主机控制，比较实际世界结果，个人内容另按冻结预期核对。原版控制并非把个人世界重复执行一遍。

验收包含缓存辅助函数、修改前后查询、新增结束帧查询、数值交换、表达式贡献、个人语言分支与保存、重建、重复帧、绘制和保存后失败，以及私有全局和玩家 GetData 的恢复。多候选、不同分支的同一辅助函数、无法定位的新查询、未知输入、循环、随机、变更向量和过期帧均保留明确诊断。二号玩家分别使用场景中的 0 和 7；绑定旧快照时不会读到后来设置的 7。游戏场景后来变为 99 帧，绑定旧帧的查询仍显示 42。

原 World View 35 项原清单、原预期回归通过，仍为 24 项普通 API 和 11 项预期拒绝。真实 MCM、EID、组合初始化的原版对照通过，本轮组合约 0.857 秒、2563885 工作单位、62152704 字节私有内存；初始化测试没有启用游戏重放或证明完整菜单。EID 本次初始化仍未加载个人保存配置。

保持 1000 万工作单位、5 秒子进程超时、1 GiB 私有内存。单帧最多 128 操作、1024 查询、2 MiB 增量计费；整个快照缓存最多 128 帧、8 MiB，贡献绑定另有条数与字节上限。129 帧后的旧绑定会拒绝，不能默读当前状态。结构指纹使用有界缓存和子节点摘要，不展开指数大小的依赖树；报表默认导出最新完整帧和缓存摘要，可按键读取保留帧，不回读历史审计文件。

源值图、接受历史、资源和初始化预算沿用前阶段限制，没有放宽上限。仍没有源值图活跃根回收或长会话检查点；快照缓存有界不代表整个会话已完成长期内存验收。

## 尚未通过的功能门槛

随机结果和时间源尚无此模式的契约，不能在个人端自行计算；奖励控制的显示分支仍需要双视图分支求值。循环、未证明的闭包操作数、修改后的向量、重放中新出现但无法定位状态的查询也未兼容。相关拒绝是能力缺口，不能算这些模组已经支持。

同一来源对应多个权威贡献时仍拒绝。标准设置菜单边界、配置重新加载的完整侧车、同回调主机绘制捕获、全部 userdata 和原生副作用还需补齐。主机捕获阶段的绘制权限仍受原模型限制；不能据当前个人附加 HUD 案例宣称主机绘制回调已完整通过。

本轮没有启动游戏、修改安装目录或个人存档，也没有复制游戏资源或新建 ZIP/解压副本。真实渲染、原生模拟接管、网络和断线恢复、个人解锁及双机 30 分钟测试均未完成。后续先接随机契约和延迟分支，并补齐剩余查询/输入来源，再推进真实菜单和 HUD；不宣称支持任意旧模组。
