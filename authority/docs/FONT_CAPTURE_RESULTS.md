# 字体捕获结果

2026-10-17。独立 Windows x86 原型已能执行未经修改的 J460 字体兼容包装，并捕获真实 EID `renderString` 的文字输出。**完整菜单、HUD、画面和联机尚未通过。**

## 实现

新增 `font_capture_runtime` 和私有 ABI `ia-lua533-font-capture-1`，命令行入口为 `--font-capture-suite`，候选信息见 `research/font_capture_candidate_v1.json`。上一字体度量候选及全部模组源码保持原样。

原始 J460 包装 304–351 行完整执行，四种字体调用最终只在原生签名入口捕获一次。命令保存文字原始字节、已校验资源及哈希、坐标、缩放、KColor、六个绘制设置和状态版本；后续对象修改不改变旧命令。不调用游戏绘制后端。

FontRenderSettings 使用受控 userdata、独立代次、六个字段版本和 GC 回收。资源和外部字段依赖在读取时登记。失败恢复从初始源码及已接受事件重建，已暂存的配置、私有计数、字体、设置、颜色和绘制队列一并撤销。命令用途仍标为 `unclassified`，世界投影和发布保持关闭。

设置默认值依据已有 J460 原生观察的一个有哈希的字节区间核对，每次初始化只读该区间一次。旧包装创建设置后仅修改对齐，其他五项取值有观察依据；**构造器默认对齐没有独立证明，读取或绘制未显式设置对齐的对象仍拒绝**。没有将未知值补成成功结果。

## 验证

- 48 项新检查完整执行两轮：26 项功能/恢复、22 项明确拒绝，各自达到冻结预期。覆盖缓存函数、四个字体入口、居中/右对齐、原始字节、快照不可变、个人配置与位置、主机一次奖励、保存重建、失败恢复、字段失效、A→B→A、GC 及容量保护。
- 原 64 项字体清单与 44 项真实框架回调清单保持原结果，未改变旧预期。
- MCM、EID、组合初始化继续完成。真实 EID 及组合环境通过公开回调调用未经修改的 `EID:renderString`，准确产生 `native bridge` 的字体命令；比较了全部文字、资源、颜色、坐标、缩放和设置，而非仅命令数量。
- 从成功案例取得的 57 个字体命令帧、59 条命令，通过现有原生 `validate_draws` 及 CBOR 编解码往返。另验证无效字节编码、资源越界、无效坐标、设置类型和超大消息均拒绝。这没有测试网络连接或游戏重放。
- 子进程均保持 1000 万工作单位、5 秒、1 GiB 配额，没有启用全量追踪、扩大预算或启动游戏。完整结果直接压缩，不复制图片、字体或模组资源。

## 未通过的完整回调

直接执行冻结模组完整 `MC_POST_RENDER`，三个案例均为功能失败，保留在 `font-capture-probes-v1`，没有改成兼容通过或空操作：

| 案例 | 首个未支持入口 |
|---|---|
| MCM | `Game.IsPaused contract not implemented` |
| EID | `Sprite.Update contract not implemented` |
| MCM → EID | `Game.IsPaused contract not implemented` |

下一步为权威场景快照补齐暂停状态查询，再依据实际动画数据实现推进和捕获。之后继续驱动真实菜单输入与完整 EID HUD。框架消费者读取集、可信菜单用途、混合回调双视图、连续会话内存、原生世界接管、通信、个人进度及双机验收仍未完成。

当前每帧队列上限为 1 MiB，原有单消息协议上限为 512 KiB；超大字体帧和超长字段在接入实际传输前还需要分片或独立传输设计。本轮通过的样本最大编码消息为 1,409 字节，不能据此推定所有允许捕获的帧都能直接发成一条消息。
