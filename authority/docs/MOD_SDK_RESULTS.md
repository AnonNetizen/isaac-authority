# 多模组注册、个人数据与 J460 枚举接入结果

独立 Windows x86 候选 `ia-lua533-mod-sdk-1` 已接入注册身份、按来源目录隔离的数据、回调归属及完整冻结枚举。本轮 35 项 SDK 模型和 235 项旧模式分类回归达到各自预期；**真实 MCM/EID 完整初始化仍未通过**，三个入口现在都明确停在未接入的 `Vector()`。

保持 1000 万工作上限、5 秒子进程超时及 1 GiB 配额。没有启动游戏、修改原模组或个人存档，也没有开启全量追踪。旧模组不改、个人配置独立、奖励跟随主机仍是完整目标，本轮没有开放自动投影、菜单导航、绘制重放或通信。

## 注册、数据及回调

执行冻结引擎 `resources/scripts/main.lua` 原始第 1–28 行、803 字节的 `RegisterMod` 包装函数，保留其中对 `Isaac` 方法的动态调用。全文件和片段分别校验 SHA256，没有改写这段函数；其余引擎启动兼容函数尚未完整接入。包装函数会被真实 MCM 的 FilepathHelper、CustomCallbackHelper 原样包裹，模型后端仍识别实际注册表。

注册身份依据当前上下文内实际 Lua 表，回调保存所属注册编号。Name 的修改、重名或缓存方法不改变接收者的数据归属。辅助库可能在同一模组目录内注册多个引用；模型按来源目录、固定存档槽及玩家上下文分别保存数据，同目录辅助引用共享目录数据。接口与存储位置依据 [Isaac API](https://wofsauge.github.io/IsaacDocs/rep/Isaac.html) 和 [Mod Reference](https://wofsauge.github.io/IsaacDocs/rep/ModReference.html) 核对；具体引擎目录映射仍需原生验证，研究存储没有接到游戏文件。

加载器保留当前主入口目录，调用回调时恢复所属目录，因此经另一个目录定义的全局包装函数注册时，不会被最近一层辅助源码误归属。SDK 启用时模块搜索也使用该受控活动目录；未启用时保持旧模式规则。同名模块的跨目录缓存及完整引擎模块环境仍待原生核对，不能由本轮模型推导为任意模组等价。

原始 SaveData 字节直接保存到私有研究内存，支持空字符串与缺失状态的区别；LoadData 缺失时返回空字符串。报告使用 `present` 和十六进制 `data_hex` 表示数据，避免 JSON 报告破坏非 UTF-8 字节，模组实际保存的数据和 JSON 格式不变。单目录数据上限 1 MiB，每个玩家上下文总量 16 MiB。

内容版本和存在性版本分开记录：改变其他目录不使本目录读取失效，内容修改不必使只查询 HasData 的读取失效；删除后恢复、内容 A→B→A 会使相应旧读取失效。校验只查实际读取的目录，不回读审计文件。保存、两个目录数据、私有 Lua 状态及绘制后的失败经检查点和已接受历史重建。

回调按优先级及注册顺序运行；移除同一函数时只影响指定注册表。过滤参数采用冻结引擎默认匹配规则中的 nil、-1 和相等匹配。非 nil 返回值会停止该次分发，包含 false。当前支持模型的整数回调编号、整数过滤参数和数据参数，实体参数、完整回调表及重载行为仍未全部接入。

## 冻结枚举

完整执行未经修改的 `enums.lua`，158,046 字节，SHA256 为 `9737fc06f15ea26f397f8abe4ade01af105bdae1bec54b7ffbeacedd549dadb0`。为其提供受控 BitSet128 构造和只读 l/h，以及 ItemConfig、RoomDescriptor 的枚举常量容器；不支持的方法、字段写入和命名空间操作继续拒绝。没有手填 Keyboard 或跳过 TearFlags。

完整规范化枚举导出为 158,508 字节，SHA256 为 `ee28c5634b77b7294240030368101e517f57520d58e48a44ba0125fd06b167b7`，与独立原版 Lua 及重复候选一致。覆盖 64 位符号位和高半部；每个上下文保留 109 个由原枚举产生的 BitSet128。该样本使用 143,725 工作单位、约 0.044 秒原生时间，未创建全值依赖图。

真实入口清单的 REPENTANCE、REPENTANCE_PLUS 标志来自冻结 J460 引擎 main.lua 的实际赋值，两者均为 true；不从当前公开文档反推旧版本环境。原版 Lua 对照使用相同登记后端，因此证明的是语言执行和模型结果一致，不能替代原生对象 ABI、游戏行为或画面验证。

## 修复与历史记录

1. 原始字节已正确保存在 Lua/模型中，但最初向 JSON 报告输出 `0xFF` 失败。改为报告层十六进制后，字节往返和私有数据恢复通过。原失败二进制、源快照和报告保留。
2. 旧模式延迟加载回归出现偶发未知 userdata 拒绝。只在失败路径增加至多 32 个元表项的类别诊断，复现出 `FILE*`：原初始化创建 io 文件对象后又隐藏 io，延迟 GC 时撞上读取检查。新入口不初始化本就不开放的 io 库；其余标准库按原顺序加载，未知 userdata 检查保留。原同一冻结案例随后连续 24 个有超时的子进程完成，235 项旧回归达到原预期。诊断版及修复前二进制和源快照均保留，不能把偶发失败重跑成功称为修复。
3. 初版测试错误地要求两个原包装方法一定不同，随后又错误地固定为相同。原版 Lua 也随内部缓存给出两种结果。[Lua 5.3 §3.4.4](https://www.lua.org/manual/5.3/manual.html#3.4.4) 明确允许这种闭包身份差异。V1/V2 及失败诊断原样保留，均不计兼容通过。V3 使用独立案例检查不同注册表及缓存方法对实际接收者的读取；并新增实际改变 Name 的案例，原 33 项其余案例不变。原模组与引擎包装函数均未修改。

- 代码：`sdk_runtime/`；当前清单：`research/mod_sdk_v3.json`，真实清单：`research/mod_sdk_real_v2.json`。旧清单、原模组与前一候选保留。

- 只读校验：`python -B authority/tools/verify_mod_sdk.py`。校验成功保留整体 `gate_passed=false`，不代表真实模组初始化、HUD 或任意模组兼容通过。
