# 日志与物品配置后端的下一步

保留值对象候选及其全部报告，派生独立 `--services-suite` / `ia-lua533-engine-services-1` 入口。正式 1000 万工作单位、5 秒子进程超时、1 GiB 提交配额不变，不再运行无配额测试。

封存前更新为 `ia-lua533-engine-services-2`：弱引用扫描次数、峰值及字段读写次数保留在顶层成本统计中，不混入 `value_status` 的可重放状态。原 `-1` 二进制、失败记录及源码快照保留，原冻结案例源码和功能预期不变。

1. `DebugString` 捕获原始消息字节及模组目录、主客身份、执行阶段，写入私有事务记录，不写游戏日志。按公开接口核验单字符串、无返回值；超过已登记消息长度和未核实的嵌入 NUL 明确拒绝，不猜测原生截断。记录数量和总字节都有上限，分配前计费。失败从初始化及已接受历史重建，未提交记录不得保留。
2. `GetItemConfig` 返回受控只读配置对象。复用先前已保存的 J460 原生只读查询证据，先冻结实际记录到的四种物品 ID，以及实际导出的 Sad Onion 名称字节和质量。目录是部分快照，未捕获的 ID 或字段报错；不能把“快照未覆盖”当作“不存在”返回 nil。提供通用快照查找后端，不按模组名判断。
3. 配置 userdata 有上下文代次、受控身份、实际接收者检查和字段级读取标记。不可写入，未知方法拒绝。每个上下文只保留一个服务对象及有限惰性条目缓存；只读数据共享，个人配置及日志独立。
4. 原版 Lua 和研究 Lua 对照：返回值、原始字节、缓存方法、消费者读取、个人配置/主机金币、失败恢复及资源拒绝。原有 40 项及 270 项按原预期回归；真实 MCM/EID 及组合分别短测，记录首个新失败。

文档核对入口：[Isaac](https://wofsauge.github.io/IsaacDocs/rep/Isaac.html#debugstring)、[ItemConfig](https://wofsauge.github.io/IsaacDocs/rep/ItemConfig.html)、[物品字段](https://wofsauge.github.io/IsaacDocs/rep/ItemConfig_Item.html)。这些文档支持接口形状；J460 实测记录支持快照中的实际数值。均不能证明未捕获字段、运行中的解锁状态、完整物品池、当前所有模组内容或原生对象相等行为。

只有真实初始化完成后，才继续相应的菜单/绘制门槛。完整目标仍是旧模组不修改、个人配置独立、奖励跟随主机；部分服务接入不构成该目标通过。
