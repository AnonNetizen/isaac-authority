# 紧凑观察记录与延后 JSON 导出

上一轮同源码百万读取为 50.0206 秒/0.4705 秒，可选观察层是下一步有证据的瓶颈。本轮恢复 1000 万、5 秒和原有全部容量规则；保留原候选、无配额测量及冻结源码，不重新开启全量追踪。

1. 新建独立 x86 候选 `ia-lua533-compact-values-1`。读取时用带类型的标量、寿命编号、版本和调用实例，字符串只在实际记录变化时取得所有权。禁止保留 Lua 字符串或对象裸指针。
2. 未被快照引用的记录原地更新；已有快照引用时复制变化记录，保护旧时点。观察编号随逻辑变化递增，相同值的写入版本变化不能去重。返回、异常、GC 与新捕获沿用原回收边界。
3. 用不分配的 JSON 字节长度计算维持原收费与 256 KiB 判定；在多种标量、边界字符串和三种记录上与真正 JSON 编码交叉校验。现有容量拒绝保持，不能靠少计工作或放宽配额获得性能。
4. 导出时才生成原协议 JSON，复用独立原版 Lua 验证器。原 21 项与 129 项旧回归，另做 5 秒/1000 万以内的同源码开关短基准；保持来源、缓存复用和主机投影开关关闭。

本轮优先消除热路径分配并验证时点证据。真实 MCM/EID 的模块加载和 Game() 接入、调用摘要与主机奖励仍是后续要求，不能因模型优化通过而宣称完成。
