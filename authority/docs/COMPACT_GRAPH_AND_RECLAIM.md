# 紧凑图、审计存储和安全点回收

本轮只验证独立 Windows x86 命令行研究运行时。旧模组源码、安装目录及个人存档不变；1000 万工作单位上限不变。个人设置与主机游戏视图沿用 `personal-settings-authority-hud-v1`，没有改为共同配置，也没有删回调或隐藏 HUD。

候选 ABI 为 `ia-lua533-slice3-ui-compact-1`，新清单模式为 `ui-compact`；回归入口同时接受原样的 Incremental2 清单。游戏加载器未改动，不应把这个私有 DLL 装进游戏。真实 MCM/EID、游戏渲染、世界接管、联机和解锁尚未验收。

## 实现

节点常驻表示为类型化标量、生产者编号、数据/控制操作数、共享源码位置以及字段/upvalue 版本。整数和浮点位模式、原始字符串字节保持；扩展操作元数据使用 CBOR，不常驻 JSON DOM。原消费者读取时临时解码，读取和编解码成本计入账本。普通 Lua 的结果不能因存储格式改变。

历史节点、存储版本、消费记录、用途、源码目录及缓存证据写入追加式审计文件。操作和位置目录也随文件保存；另一个 Python 解码器无需 Lua 状态即可重建这些证据，与导出逐项比较。记录头和负载分别校验 CRC32，宿主对整个文件再做 SHA256。哈希只能筛选描述符，命中后仍读取原始描述并精确比较。

热缓存限制为 4096 个节点、8 MiB 有效负载，目录管理开销由 DLL 堆配额约束。旧记录退出热缓存后仍可按原编号从审计文件加载；没有回收后复用生产者编号。去重字典使用固定 4096 个桶头，其历史键留在磁盘，不再在内存保留全部字符串。索引发布在对应记录写完后进行。

安全点回收读取 Lua 当前堆、活动执行上下文和显式宿主引用，清理已死亡对象的字段、反向边、upvalue、字符串键和原型索引。已结束父调用的子调用计数也可移除，根调用序号继续单调增长。个人/主机视图侧表按实际求值器的操作数关系判定存活；历史结构证明边完整留在磁盘。保存的序列化形状作为额外依赖处理。

宿主持有的历史值必须声明 pin。未声明且已回收的权威引用再次被查询时明确拒绝，不能降格成个人值。注册 userdata 的隐藏根尚无完整适配，因此当前回收入口会拒绝这类上下文；这属于尚未支持，安全拒绝不算模组兼容通过。

## 资源边界

| 项目 | 实际边界 |
|---|---|
| 工作量 | 每研究上下文 10000000；同一例的初始化和全部阶段累计，不逐段清零 |
| DLL C++ 堆 | 全模块 `new/delete` 统一计量，上限 512 MiB，含分配头与对齐保留量 |
| 进程 | Windows Job Object：1 GiB 私有提交，包含 Lua C 堆和宿主 |
| 单条审计记录 | 8 MiB 负载上限；I/O 按 64 KiB 分块 |
| 每例审计文件 | 4 GiB；写入前检查 |
| 原有逻辑限额 | 262144 个图节点、65536 个描述符及旧逻辑证据限额保留 |
| 测试宿主 | 每次执行 90 秒，诊断输出 64 MiB |

512 MiB 计量针对私有 DLL 的 C++ 堆，不包括 Lua 的 C 分配器、CLI 宿主或 Python 验证器；这些不能写成“全系统总内存不超过 512 MiB”。8 MiB 是单条负载限制，也没有证明所有瞬时编码对象总和都不超过 8 MiB。

历史文件仍会增长，必要的编号索引也会增长；其规模受以上限额约束。真正新增的存活变量需要内存。因此本轮证明的是临时对象和常驻历史副本得到回收/移出内存，不承诺任意程序无限运行时内存一字节不增。

I/O、校验、索引、编码、回收和导出均有工作分类。没有通过扩大 1000 万、隐藏费用或清零累计工作量来通过。审计损坏、关闭文件、磁盘限额、工作量或堆限额失败，均拒绝该次执行。失败路径保持 DLL 映射直到异常销毁，避免先卸载 DLL 再调用异常虚函数造成崩溃。

## 验证与限制

原样回归前一阶段 24+27 个案例，逐项比较普通结果、错误、原始字节、全部生产者图和缓存证据；独立解码审计文件再次比较。新增 13 个存储案例覆盖循环垃圾、闭包、别名、主客数值交换、宿主 pin、歧义及资源/I/O 拒绝。报告分别记录功能兼容和安全拒绝。

本轮最终清单共 64 项：53 项功能检查、1 项普通 Lua 错误行为对照、10 项预期安全拒绝。每项运行两次，拒绝案例不计入功能兼容通过数。

循环测试在同一上下文连续执行 24 批，每批生成 32 个含循环引用及闭包的临时对象。对照例关闭索引回收，回收例保留相同 Lua 源码、输入和结果。对象索引在对照中持续增长，回收例保持 3；回收例的剩余堆增长主要来自必要审计索引扩容，原始采样保留在报告中，不用一个宽松阈值宣称绝对恒定。

双视图案例检查个人 amount=2 时仍保存/读取 2、普通 HUD 求值为主机的 1，语言 en、位置 137 保持个人值；交换 1/2 后也检查反向结果。该后端模拟已存在的 JSON 字段来源契约，不是真实设置菜单或 SaveData 存档验收。真实 userdata 根、持久宿主历史和 MCM/EID 对象桥须在下一阶段接入并验收。

旧 13/31/24/42/56 模式整套联机模型没有在本轮重新认定通过。旧源码、二进制与冻结清单保持原位；本轮 51 项是 Incremental2 存储回归，不能混称旧全部兼容门槛。

## 运行与复现

```powershell
python -B authority/tools/run_compact.py --storage journal --output authority/reports/ui-compact/new-regression
python -B authority/tools/run_compact_storage.py --output authority/reports/ui-compact/new-storage
```

输出目录必须不存在。`--storage memory` 保留紧凑内存表示作为对照。测试不会启动游戏。常规入口只读取存档哈希用于保护核对；解压复现入口不读取个人存档。

增量研究包依赖已保留的 `isaac-incremental2-native-effects-v2.zip`，SHA256 为 `74f934c1772242fbffb959515df4c826235da21132dfea58ae66f53e6e44a611`。不嵌套这个 ZIP，不再次复制其静态库、Lua 和旧冻结源码。两包结合后包含重编译输入与预编译原型。

```powershell
python -B authority/tools/reproduce_compact.py --base authority/artifacts/isaac-incremental2-native-effects-v2.zip --delta authority/artifacts/isaac-ui-compact-v1-delta.zip --workspace authority/build-ui-incremental2/compact/unpacked-release --output authority/reports/ui-compact/unpacked-release
```

入口核验两包、逐文件哈希与冻结输入后，每例运行两次；比对语义、引用、恢复拒绝和审计字节。结果保留在解压树外。复现后使用 `cleanup_compact_replay.ps1` 核对清理计划中的每个文件，逐文件移除重复解压内容；不递归删除未知目录。重复运行的两份审计若字节一致，也仅保留一份。

构建复用 `build-ui-incremental2/compact`，只保存一个活动构建；派生后内容相同的生成源码保留时间戳，避免修改宿主报告就重编全部 Lua。历史失败报告及其已记录二进制哈希保留，未用新通过结果覆盖。
