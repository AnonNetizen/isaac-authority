# 精灵状态与冻结资源接入顺序

从服务候选派生独立 CLI，保持旧二进制、原始清单和失败证据。继续 1000 万工作单位、5 秒子进程超时及 1 GiB 配额；不启动游戏、不修改模组或存档。

1. 冻结已保存原生预检中的 7 个精灵资源、ANM2 动画边界及主动画帧读数。请求时间线帧与 `GetFrame()` 的主动画帧分别保留；光标请求 4、原生返回 0 的反例原样验证。原样执行 J460 的 SetFrame/Load 包装片段。
2. 为打包资源建立字节范围证明：先核对历史整包 SHA，再冻结头、完整索引及所选成员的编码数据范围。CLI 按固定提供者验证这些范围，持有禁止写入/替换的读取句柄；同一会话只校验相同范围一次，成本全部计入预算。不把其他未读包内容说成已经重新校验，也不猜测当前游戏的覆盖优先级。
3. 接入 Load、SetFrame 两种形式、GetFrame/GetAnimation、已登记的 Play 起点及 Color 写入。保留请求参数和有序操作，字段版本区分资源、动画、帧及颜色。未覆盖的连续播放、Update、Color 返回值别名和渲染继续拒绝。队列有每对象及全上下文配额，退休时回收。
4. 原版 Lua 对照、原生读数对照、缓存函数、字段精度、ABA、GC、失败恢复、个人设置和主机金币短测通过后，复测 MCM/EID/组合及旧模式。输出明确的真实初始化通过或失败，不把接口拒绝算作功能兼容。

参考 [Sprite API](https://wofsauge.github.io/IsaacDocs/rep/Sprite.html)。原生读数支持已记录的 SetFrame/GetFrame 控制，公开接口支持模型形状；完整图层画面和连续动画仍需以后集中核对。
