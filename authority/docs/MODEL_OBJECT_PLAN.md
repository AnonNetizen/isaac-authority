# 对象与资源契约第一步

上一阶段真实 MCM 在 Sprite() 停止，EID 在 Game() 停止。本阶段沿用冻结模块候选，新增独立对象/资源入口，不修改原模组，不启动游戏，不放宽 1000 万、5 秒和 1 GiB 限制。

1. 实现带上下文代次、稳定本地编号和 GC 回收的 userdata；缓存方法必须仍校验当前 receiver，未知属性或方法报错。Game 用明确模型快照提供已登记查询，不返回空房间/实体来绕过 EID。
2. Sprite 构造与加载保持真实资源身份。冻结现有目录里的 ANM2 默认动画、层及所有图片依赖，校验原哈希，不复制资源。只提供有契约的加载/元数据查询；Reset、播放时间线和渲染没有足够证据时继续拒绝。
3. 对象修改保留版本，读取接到消费者的外部依赖。失败经既有重建恢复对象状态、配置和队列；删除/GC 使旧对象依赖失效，不能因地址复用恢复有效。
4. 复用原 FilepathHelper 失败源码和真实 MCM/EID，使用独立 stock Lua 对照普通行为。分别记录 constructor/资源模型契约与真实接口门槛，不把下一个未支持入口算成功，不添加模组特判。

参考：IsaacDocs Sprite、Game API；冻结本地 XML 为资源内容依据。旧 UI 后端的永久保活及未验证动画更新规则不沿用。此阶段不宣称原生游戏等价、完整菜单/HUD 或主机奖励投影通过。
