# Slice3 金币模型研究

本候选使用固定规则 `personal-settings-authority-hud-v1`：可信标准设置菜单读取个人值；普通 HUD 中已唯一关联世界贡献的值与显示条件读取主机游戏视图。其他语言、位置和输入保持个人值。这是约定的行为，不是对模组作者意图的推断。同一设置显示在普通 HUD 中时，其显示可能改变。

这是独立 Windows x86 Lua 5.3.3 金币模型，私有 ABI 为 `ia-lua533-slice-3`。它不加载游戏进程，不替换游戏 DLL，不同步真实房间或实体，也不是可使用的联机修复。

## 实现

`slice3_runtime` 从 Slice2 派生并独立编译；原来的运行时、冻结清单、报告和研究包保持原样。个人 Lua TValue 不被主机值覆盖。运行时在侧表保留变量、字段及 upvalue 版本的游戏引用，按用途在显示消费端求值。JSON 字段具有独立来源身份；算术、复制、拼接和已登记原生调用使用有序操作数，不从来源标签集合猜算式。

主机正常执行一次。世界修改根据已有的回调、动态调用上下文、操作身份和状态时间点匹配唯一权威记录。多个无法区分的生产者、未知投影操作、未知查询时间点继续拒绝。随机调用在个人环境产生未解析表达式，不能返回伪造的随机结果。

具体值的显示分支与未解析奖励分支都可暂存探索。对于一个分支影响显示状态的情况，候选路径提供实际 HUD 消费及控制依赖；将相同调用上下文、生产者和动态条件位置的用途证明合并后，重新校验各路径。只提交唯一一致的路径。每帧最多 32 条路径、8 个未解析条件、200 万探索工作单位。账本包括可信引导代码计数、模组初始化、历史重建、解释器指令和投影值求解。

版本图保存每个来源版本在各帧对应的权威引用。跨帧读取旧的字符串或闭包变量时使用产生该版本时的视图，当前字段读取使用当前引用。个人保存仍使用个人计算结果；已解析世界查询和奖励保存实际结果。JSON 格式不增加网络字段，配置元数据在运行时侧保存并通过已接受历史重建。

## 设置菜单边界

本阶段只验证共享框架模型，调用契约参考 [MCM API](https://github.com/Zamiell/isaac-mod-config-menu/blob/main/docs/api.md) 的 `AddSetting`、`CurrentSetting`、`OnChange` 和 `Display`。模型框架源码哈希和 Change/Render 函数原型身份由运行时登记。嵌套用户回调在真实框架调用栈内读取个人值；离开调用栈后，同一缓存函数用于普通 HUD 时按 HUD 规则处理。模组名、函数名或自称菜单的字段不能授予设置用途。

模型文件 `fixtures/slice3_menu_provider/main.lua` 是测试框架，不是完整 MCM。真实 MCM/EID 的菜单、资源、输入与画面没有在本轮验证。

## 运行和验收

构建：

```powershell
./tools/build.ps1 -BuildDirectory build-slice3 -RuntimeOutputDirectory build-slice3-release/Release -TraceResearch -SliceResearch -Slice2Research -Slice3Research
```

冻结主清单为 `research/slice3_suite_v3.json`。其中原 55 项预期未改，新增序列化来源丢失拒绝案例；有序算术操作数案例仍保留。两个原反例复用原文件，包含交换主机和个人数值的检查。案例核对菜单/HUD、位置、保存与重载、别名、闭包、缓存函数、动态代码、跨帧值、显示分支、拒绝、恢复和去重。

命令行运行：

```powershell
py tools/run_slice3_suite.py --binary build-slice3-release/Release --game '<游戏目录>' --root . --manifest research/slice3_suite_v3.json --output '<新报告路径>'
```

完整验证使用 `tools/run_slice3_research.py`，按原模式运行原 13、31、24、42 项清单两次，另跑 Slice3 清单两次并比较整个报告。普通 Lua 行为对照和私有 ABI/规则拒绝检查单独记录。需要兼容的案例被拒绝仍算功能失败，预期拒绝只算诊断正确。

交付包带逐文件哈希、完整当前报告、历史失败记录、Slice2 原包和可复现入口。先运行 `tools/verify_bundle.py` 校验并解压，再运行 `tools/reproduce_slice3.py` 校验解压文件并复现模型输出、用途证明、状态锚点、分支及预算账本。

## 能力边界

支持范围由冻结案例及登记的操作契约定义。没有可信设置入口的绘制按普通 HUD 处理。未知原生投影操作、缺少来源、多个权威贡献、无法唯一确定的状态时点和超出预算都拒绝。没有逐模组补丁或用户源码标记，也没有隐藏界面来绕过验收。

有限金币模型通过不代表任意旧模组兼容。真实 MCM/EID 接入、原生世界接管、通信、个人解锁和双机 30 分钟验收仍是后续工作。
