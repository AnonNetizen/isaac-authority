# 独立 x64 初始化工作量估算

本次经用户选择，使用独立 Windows x64 命令行运行时估算冻结 EID 和 MCM+EID 的完整初始化工作量。未启动或附加游戏，未写入个人存档或安装目录配置；正式 x86 的 1000 万上限、源码、DLL 和既有清单保持不变。

入口为 `tools/probe_incremental_x64_completion.py`，依次执行 `prepare`、CMake x64 Release 编译、`preflight`、`run`。所有阶段使用同一 `--directory`。派生源码和大文件放在 `%TEMP%/isaac-x64-sizing-20261011`。

临时估算限制为 20 亿工作单位、单次逻辑遍历 262,144、深度 256、编码证据 8 GiB、描述 524,288、图节点和消费记录各 4,194,304。其他源代码、CFG 和指令预算沿用既有值。保留底层完整记录及逐次收费，只精简检查桥读取的诊断副本，不导出最终完整依赖报告。不会将这些限制写入正式版本。

从冻结官方 Lua 5.3.3 构建未修改的 x64 参考 DLL，并重新编译原生后端；没有链接 x86 库。27 个冻结小案例对照参考返回值、字符串字节、错误和可观察表状态，合计通过 17,985 次同 VM 来源遍历对照；upvalue 普通结果一致。两个原边界程序返回 1，同一上下文的完整和精简检查输出费用完全相同。预检查先前两次失败记录保留：原因是测试适配器在关闭追踪时仍调用来源标记；最终适配器按模式关闭该测试标记，不修改模组源码或 Lua 执行规则。

64 位指针、对象大小和 Lua 哈希布局与 32 位不同，因此这里是 x64 估算，不能称为精确 x86 总量。费用范围是 J460 枚举、冻结模组初始化和既有契约检查，按上下文生命周期累计；不是一帧费用，也不是游戏帧耗时。`personal-settings-authority-hud-v1` 与独立个人配置规则不变；此测量不验证奖励、菜单导航或真实画面。

在用户质疑资源使用及实现路线后，停止了本次独立测量。停止前观测到 EID 进程 CPU 时间 845.609 秒、峰值工作集 12,871,643,136 字节（约 11.99 GiB）、私有提交 13,660,426,240 字节；模块加载尚未完成，组合案例尚未开始。CPU 时间不能当作墙钟时间，观测峰值也不是完整初始化的峰值。没有测到完整总量，不将预检查通过算作真实加载通过。

停止后重新校验 31 个个人存档/配置文件、冻结输入、正式 DLL、正式研究源码、派生源码及重编译的原生源码，均未改变。汇总报告路径为 `reports/ui-incremental-x64-completion-sizing.json`，状态为 `interrupted_for_architecture_review`；历史 x86 失败报告及 x64 预检查原始记录均保留。成本诊断见 `INCREMENTAL_UI_TRACKING_COST_REVIEW.md`。
