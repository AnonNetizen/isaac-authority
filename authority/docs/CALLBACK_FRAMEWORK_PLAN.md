# 直接使用冻结的 J460 回调框架

前轮真实 EID 在字符串事件注册处被旧整数后端拒绝。本轮使用原 J460 main.lua 第 41–163 行的完整回调实现，源码按哈希核对，不修改模组或该框架片段。每个私有 Lua 环境拥有自己的原始回调表；优先级、过滤、false/nil、动态修改和嵌套运行由原 Lua 代码决定，不新增 EID 专用规则。

1. 新增独立 `--callback-suite` / `ia-lua533-callback-framework-1`，冻结框架边界和契约。使用临时局部 debug 表提供框架唯一需要的 getinfo，仍不公开 debug 库。
2. 原生桥只负责事件类型和容量检查、数值内建事件的启用状态模型、受控转发及错误恢复。补齐嵌套 protected_call 的钩子保存/恢复，避免内部调用关闭外层配额钩子。回调表总量上限沿用 256，嵌套转发上限 32。
3. 主机和个人上下文通过原 RunCallbackWithParam 调度；个人不能进入 authority 阶段，世界修改仍受原守卫。新框架的精确消费者读取集尚未接入，capture_* 明确拒绝，不能输出伪造的绿色依赖证明。旧框架模式保留。
4. CLI 短测覆盖整数与字符串身份、原始字符串字节、优先级、false/nil、匹配参数、缓存方法、嵌套参数与返回、增删回调、上下文及配置隔离、错误恢复和预算。对照未修改 Lua，再原样回归前轮模型，尝试真实 MCM/EID。

保持 1000 万工作单位、5 秒子进程和 1 GiB 配额。不启动游戏，不修改存档，不重启全量追踪；真实初始化和 UI 门槛继续独立计为未通过。
